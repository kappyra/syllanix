# Безопасность проекта

## Поддерживаемые версии

Актуальная ветка `main`. Исправления безопасности выпускаются для неё.

## Как сообщить об уязвимости

**Не создавайте публичный issue.** Напишите на адрес, указанный владельцем
репозитория (см. профиль GitHub), или воспользуйтесь GitHub Security Advisories
(вкладка Security → Report a vulnerability). Укажите:

- затронутый компонент (сайт, EPUB, Markdown-конвейер, workflow);
- шаги воспроизведения и минимальный пример;
- ожидаемое и фактическое поведение;
- возможное влияние.

Мы подтвердим получение в течение 7 дней и сообщим о плане исправления.
Пожалуйста, дайте разумное время на исправление до публичного раскрытия.

## Что является уязвимостью

- XSS/инъекции в собранном сайте (включая SVG/HTML, генерируемые из Markdown);
- подмена ресурсов или исполнение внешнего кода (в текущей поставке внешних
  ресурсов нет, CSP запрещает сторонние скрипты);
- утечка секретов в репозитории или артефактах;
- уязвимые зависимости проекта;
- компрометация CI/CD (workflow, артефакты Pages).

## Меры безопасности в проекте

- CSP и `Referrer-Policy` в каждой странице; внешних `link/script/img` нет;
- SVG-файлы проверяются машинно: запрещены `<script>`, обработчики `on*`,
  внешние `href`, `<foreignObject>`;
- код примеров в книге не исполняется со стороны читателя: сайт — статический;
- секреты не хранятся в репозитории; сканирование — `reports/security-audit.md`;
- GitHub Actions закреплены по commit SHA, `persist-credentials: false`,
  минимальные права (`contents: read`, `pages: write`, `id-token: write`);
- зависимости аудируются (`pip-audit`), статический анализ — `bandit`.
