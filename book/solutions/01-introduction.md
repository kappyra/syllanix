# Решения к главе 1

## 1. Проверка версии {#sol-ch01-01}

```console
$ python3 --version
Python 3.14.4
```

Номер версии состоит из трёх чисел: major, minor, patch. Для книги важны
первые два. Ориентир — 3.14, потому что на этой версии проверяются все примеры.
Минимум 3.11 выбран потому, что в 3.11 появились заметные улучшения
производительности и сообщений об ошибках, а используемый в книге синтаксис
(например, `int | str` в аннотациях типов) работает начиная с 3.10–3.11.

## 2. Язык и реализация {#sol-ch01-02}

**Язык Python** — правила: синтаксис и смысл конструкций. **Интерпретатор** —
программа, которая эти правила исполняет. **CPython** — конкретная реализация
интерпретатора, написанная на C; именно её обычно устанавливают.

Пример гарантии языка: «сложение двух целых чисел даёт целое число».
Пример особенности реализации: глубина стека вызовов, при превышении которой
возникает `RecursionError`, — это ограничение CPython, а не свойство языка.
Ещё пример: точный текст сообщения об ошибке может меняться между версиями.

## 3. REPL по шагам {#sol-ch01-03}

```console
>>> 2 + 2
4
```

Шаг 1 — **read**: REPL прочитал строку и разобрал её. Шаг 2 — **eval**:
вычислил выражение, получив объект `4`. Шаг 3 — **print**: вывел результат
автоматически, потому что в REPL результат выражения показывается всегда.

```console
>>> 2 +
  File "<stdin>", line 1
    2 +
       ^
SyntaxError: invalid syntax
>>> 2 + 2
4
```

Ошибочная строка не завершила сеанс: REPL обработал ошибку, показал её и
вернулся к приглашению `>>>`. Каждая введённая строка — отдельная попытка.

## 4. Файл вместо REPL {#sol-ch01-04}

В файле `hello.py` строка `2 + 2` — это выражение, которое вычисляется и
отбрасывается. В файле результат выражения не печатается автоматически, в
отличие от REPL. Чтобы увидеть `4`, нужно явно вывести значение:

```python exec
print(2 + 2)
```

```output
4
```

Это различие — одно из первых практических следствий того, что REPL и файл
исполняются по-разному.

## 5. Зачем запускать примеры {#sol-ch01-05}

1. **Проверка понимания.** Чтение создаёт ощущение понятности; запуск
   показывает, поняли ли вы на самом деле.
2. **Обнаружение различий окружения.** Версия Python, операционная система и
   настройки влияют на вывод; запуск выявляет такие расхождения.
3. **Привычка к проверяемости.** Инженер не верит утверждению без проверки;
   запуск — самый дешёвый способ проверить утверждение о поведении кода.

## 6. Навигация по книге {#sol-ch01-06}

`asyncio` — тема части 7. Ей логически предшествуют:

- **часть 1** — функции (без них непонятно, что такое корутина);
- **часть 4** — генераторы и итераторы (корутины устроены как обобщённые
  генераторы), а также функции как объекты;
- **часть 7, глава 38** — конкурентность, потоки и GIL: асинхронность нужна
  именно как альтернатива потокам для задач ввода-вывода.

Можно назвать и более distant-предпосылки: обработка исключений (часть 2) —
без неё непонятны отмена задач и обработка ошибок в асинхронном коде; модули
(часть 2) — без них не будет работать `import asyncio`.
