# Решения к главе 9

Задачи этой главы проверяются чтением и запуском. Там, где нужен реальный файл
модуля, решения показывают структуру и объясняют, что произойдёт; исполняемые
фрагменты используют модули стандартной библиотеки, чтобы вывод был
воспроизводимым.

## 1. Имя модуля {#sol-ch09-01}

Файл `text_tools.py` образует модуль `text_tools`: расширение `.py`
отбрасывается, остальное имя сохраняется. Импортировать функцию `normalize`
можно двумя способами:

```python
import text_tools

text_tools.normalize("  текст  ")
```

```python
from text_tools import normalize

normalize("  текст  ")
```

В первом случае в текущую область попадает имя `text_tools`, а функция
доступна через точку. Во втором случае имя `normalize` попадает
непосредственно в ваш код. Первый вариант безопаснее: видно, из какого модуля
взялась функция, и меньше риск перекрыть чужое имя.

## 2. Две формы импорта {#sol-ch09-02}

```python exec
import math

print(math.sqrt(9))
```

```output
3.0
```

```python exec
from math import sqrt

print(sqrt(9))
```

```output
3.0
```

Результат одинаков, а различие в том, что появляется в текущей области.
`import math` создаёт имя `math`, и функция вызывается как атрибут модуля.
`from math import sqrt` создаёт имя `sqrt` напрямую — зато теперь любое
собственное имя `sqrt` будет конфликтовать с ним.

## 3. Прогнозирование {#sol-ch09-03}

```python exec
import math
from math import floor

def floor(n):
    return round(n)

print(floor(2.9))
print(math.floor(2.9))
```

```output
3
2
```

Имя `floor` в текущей области сначала было связано с импортированной функцией,
а затем переопределено собственной, которая округляет к ближайшему целому.
Поэтому `floor(2.9)` даёт `3`. Модуль `math` живёт в своём пространстве имён,
и его атрибут `math.floor` никто не менял: он по-прежнему округляет вниз и даёт
`2`. Это наглядно показывает, зачем нужны префиксы.

## 4. Пространство имён {#sol-ch09-04}

Значение `math.__name__` — это имя самого модуля, а не имя функции, потому что
атрибут `__name__` принадлежит объекту-модулю. Модуль в Python — такой же
объект, как число или функция: у него есть тип, идентичность и атрибуты.
Атрибут `__name__` хранит строку, под которой модуль известен интерпретатору;
при прямом запуске файла эта строка равна `"__main__"`, при импорте — имени
модуля. Функции внутри модуля — отдельные объекты со своими атрибутами, поэтому
`math.sqrt.__name__` вернуло бы `sqrt`.

## 5. Стандартная библиотека {#sol-ch09-05}

Нужны функции `ceil` (округление вверх) и `floor` (округление вниз) из модуля
`math`:

```python exec
import math

print(math.ceil(2.1))
print(math.floor(2.9))
```

```output
3
2
```

`ceil(2.1)` поднимает число до ближайшего целого вверх, поэтому получается `3`.
`floor(2.9)` опускает до ближайшего целого вниз, поэтому получается `2`. Обе
функции всегда возвращают `int`. `round` без второго аргумента тоже даёт `int`,
а с аргументом `ndigits` — `float`, потому что сохраняет дробную часть.

## 6. Пакет {#sol-ch09-06}

Импорт функции из модуля пакета:

```python
from tools.text import clean
```

После этого функция вызывается как `clean(...)`.

Импорт модуля целиком:

```python
from tools import files
```

После этого функции модуля вызываются через точку: `files.read(...)`.
Пакет `tools` при этом загружается, а `__init__.py` исполняется — поэтому
держать в нём тяжёлый код не стоит. Обратите внимание на иерархию: `tools` —
пакет, `text` и `files` — его модули.

## 7. Точка входа {#sol-ch09-07}

При импорте Python присваивает `__name__` имя модуля, поэтому условие
``__name__ == "__main__"`` ложно, и вызов `main()` не выполняется. Печати нет,
но функция `main` доступна импортирующему коду. При прямом запуске `__name__`
равно `"__main__"`, условие истинно, и `main()` вызывается. Проверим логику на
модели имени:

```python exec
def main():
    print("работаю")

module_name = "app"

if module_name == "__main__":
    print("прямой запуск")
else:
    print("импорт: main не вызывается")
```

```output
импорт: main не вызывается
```

Именно поэтому проверку называют точкой входа: она отделяет запуск от импорта.

## 8. Исправление ошибки импорта {#sol-ch09-08}

`ModuleNotFoundError` означает, что интерпретатор не нашёл модуль по путям
поиска. Если `pricing.py` лежит рядом с запускаемым файлом, при `python
cli.py` каталог скрипта попадает в `sys.path[0]`, поэтому причину стоит искать
не в текущем каталоге, а в имени файла или способе запуска.

Первая: имя файла не совпадает с именем модуля. Регистр важен: `Pricing.py` —
это модуль `Pricing`, а не `pricing`; расширение должно быть `.py`, а файл —
сохранён на диск. Проверка: выведите список файлов каталога и сравните имя
символ за символом; после успешного импорта `pricing.__file__` покажет, какой
именно файл загружен.

Вторая: программа запущена не как скрипт, а как модуль (`python -m
package.cli`) из другого корня. Тогда в `sys.path` попадает текущий каталог, а
не каталог пакета, и `pricing.py` может оказаться вне путей поиска. Проверка:
напечатайте `sys.path` и `sys.modules`; запустите `python cli.py` из каталога с
файлом или `python -m cli` из нужного корня.

Ещё одна возможность — имя `pricing` уже занято другим пакетом в окружении:
тогда импорт найдёт его. Проверка — `pricing.__file__` после импорта. Во всех
случаях правильное решение — привести структуру проекта в порядок, а не
дописывать пути в `sys.path` вручную.

## 9. Библиотека и программа {#sol-ch09-09}

```python exec
def double(n):
    return n * 2

def main():
    print(double(21))

if __name__ == "__main__":
    main()
```

```output
42
```

Теперь при импорте этого файла определится функция `double`, но печати не
произойдёт: вычисления отделены от вывода, а вывод вызывается только из точки
входа.

## 10. Мини-задача: разбиение на модули {#sol-ch09-10}

Предлагаемая структура:

- `formulas.py` — только вычисления: `celsius_to_fahrenheit(celsius)` и
  `fahrenheit_to_celsius(fahrenheit)`. Проверки ``__name__ == "__main__"`` нет:
  это чистая библиотека формул.
- `report.py` — функции вывода: `format_temperature(value, unit)`, которая
  возвращает готовую строку. Тоже библиотека без точки входа.
- `main.py` — точка входа: импортирует две предыдущие функции, получает данные
  и печатает результат. Здесь есть проверка
  ``__name__ == "__main__"`` и вызов `main()`.

Такое разделение даёт по одной причине для изменения каждого файла: формулы
меняются при изменении правил пересчёта, формат — при изменении текста,
запуск — при изменении способа ввода. Кроме того, `formulas.py` можно
импортировать в тестах, не запуская программу.

## Ответы на вопросы для самопроверки

1. Модуль — файл `.py`; имя модуля — имя файла без расширения.
2. Код верхнего уровня модуля исполняется при импорте, один раз на процесс.
3. `import module` добавляет имя модуля, доступ к содержимому идёт через точку;
   `from module import name` добавляет имя напрямую в текущую область.
4. Потому что непонятно, какие имена появились и какие существующие перекрыты.
5. Пространство имён модуля — отображение имён модуля в объекты; оно отделяет
   имена одного модуля от имён другого.
6. Пакет — каталог с модулями; `__init__.py` отмечает каталог как пакет и может
   выполнять инициализацию.
7. При импорте `__name__` равно имени модуля; строку `"__main__"` Python
   присваивает только при прямом запуске файла.
8. Точка входа — место, с которого начинается исполнение программы при запуске.
9. Потому что зависимость становится невидимой, порядок путей непредсказуем, а
   упаковка и воспроизводимость ломаются; нужны установка пакета или запуск
   через `python -m`.
