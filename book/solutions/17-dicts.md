# Решения к главе 17

Сначала попробуйте сами: решение полезно не тогда, когда его прочитали, а
тогда, когда сверили со своей попыткой и поняли расхождение. Все примеры
запускаются на Python 3.14.

## 1. Прогнозирование вывода {#sol-ch17-01}

```python exec
d = {"a": 1, "b": 2, "a": 3}
print(d)
print(list(d))
print(len(d))
```

```output
{'a': 3, 'b': 2}
['a', 'b']
2
```

Пар две: ключ `a` повторён в литерале, и осталось последнее значение `3`.
Порядок определяется первым появлением ключа: `a` появился раньше `b`,
поэтому он и остался первым, хотя значение заменилось.

## 2. Первый словарь {#sol-ch17-02}

```python exec
phonebook = {"Анна": "12-34", "Борис": "56-78", "Вера": "90-12"}
print(phonebook["Борис"])
phonebook["Глеб"] = "45-67"
print(len(phonebook))
print(phonebook)
```

```output
56-78
4
{'Анна': '12-34', 'Борис': '56-78', 'Вера': '90-12', 'Глеб': '45-67'}
```

Обращение по ключу возвращает значение; присваивание по новому ключу
добавляет пару в конец, поэтому `Глеб` оказался последним.

## 3. Исправление ошибки {#sol-ch17-03}

Тип исключения — `KeyError`: ключа `вишня` в словаре нет.

```python exec expect-error
prices = {"яблоко": 90, "банан": 120}
print(prices["вишня"])
```

```output
KeyError: 'вишня'
```

Исправление — `get` с запасным значением:

```python exec
prices = {"яблоко": 90, "банан": 120}
print(prices.get("вишня", "нет в продаже"))
```

```output
нет в продаже
```

Тот же результат дал бы явный контроль: `if "вишня" in prices: ... else: ...`.
`get` короче и не требует двух обращений к словарю.

## 4. get или квадратные скобки {#sol-ch17-04}

Квадратные скобки уместны, когда отсутствие ключа — дефект: например, в
конфигурации обязательный параметр потерян, и программе нужно об этом узнать
как можно раньше. `get` уместен, когда отсутствие ключа — нормальная
ситуация: необязательная настройка, товар, которого нет в прайсе.

```python exec
prices = {"яблоко": 90}
# обязательное поле: отсутствие — ошибка, которую лучше увидеть
print(prices["яблоко"])
# необязательное поле: отсутствие — обычный случай
print(prices.get("банан", "нет в продаже"))
```

```output
90
нет в продаже
```

Правило: `[]` — когда вы хотите, чтобы программа упала на ошибке данных;
`get` — когда хотите обработать отсутствие как значение.

## 5. Счётчик на setdefault {#sol-ch17-05}

```python exec
text = "абракадабра"
counts = {}
for ch in text:
    counts.setdefault(ch, 0)
    counts[ch] = counts[ch] + 1
print(counts)
print(sum(counts.values()), len(text))
```

```output
{'а': 5, 'б': 2, 'р': 2, 'к': 1, 'д': 1}
11 11
```

`setdefault` создаёт ключ со значением `0` только при первом появлении символа;
дальше строка `counts[ch] = counts[ch] + 1` просто увеличивает счётчик. Сумма
количеств равна длине строки — хорошая самопроверка: каждый символ учтён ровно
один раз.

## 6. Обход в порядке ключей {#sol-ch17-06}

```python exec
grades = {"Борис": 4, "Анна": 5, "Вера": 3}
for name in sorted(grades):
    print(name, grades[name])
```

```output
Анна 5
Борис 4
Вера 3
```

`sorted(grades)` возвращает новый отсортированный список ключей, сам словарь
не меняется. Если нужно отсортировать пары, подойдёт `sorted(grades.items())`:
кортежи сравниваются сначала по первому элементу, то есть по имени.

## 7. Поиск дефекта {#sol-ch17-07}

Причина падения: цикл обходит словарь, а внутри блока ключ удаляется — набор
ключей меняется во время обхода.

```python exec expect-error
stock = {"яблоко": 0, "банан": 5, "вишня": 0}
for name in stock:
    if stock[name] == 0:
        del stock[name]
```

```output
RuntimeError: dictionary changed size during iteration
```

Исправление 1 — обходить копию списка ключей:

```python exec
stock = {"яблоко": 0, "банан": 5, "вишня": 0}
for name in list(stock):
    if stock[name] == 0:
        del stock[name]
print(stock)
```

```output
{'банан': 5}
```

Исправление 2 — собрать новый словарь, не меняя исходный:

```python exec
stock = {"яблоко": 0, "банан": 5, "вишня": 0}
cleaned = {}
for name in stock:
    if stock[name] != 0:
        cleaned[name] = stock[name]
print(cleaned)
```

```output
{'банан': 5}
```

Второй способ предпочтительнее, если исходный словарь ещё кому-то нужен:
он не меняет входные сведения вовсе.

## 8. Слияние словарей {#sol-ch17-08}

Лучше всего подходит метод `update`: он добавляет пары из второго словаря,
а при совпадении ключей заменяет значение.

```python exec
defaults = {"тема": "светлая", "язык": "ru", "уведомления": True}
user = {"тема": "тёмная"}
defaults.update(user)
print(defaults)
```

```output
{'тема': 'тёмная', 'язык': 'ru', 'уведомления': True}
```

Здесь обновлён сам словарь по умолчанию. Если исходный словарь нужно сохранить
нетронутым, понадобится копия — об этом следующая глава.

## 9. Учёт на складе {#sol-ch17-09}

```python exec
stock = {"яблоко": 3, "банан": 5, "вишня": 2}


def receive(name, count):
    stock[name] = stock.get(name, 0) + count


def ship(name, count):
    available = stock.get(name, 0)
    stock[name] = max(available - count, 0)


receive("груша", 4)
receive("яблоко", 1)
ship("банан", 2)
ship("вишня", 5)
ship("айва", 1)

total = 0
for name in stock:
    if stock[name] < 3:
        print(name)
    total = total + stock[name]
print("всего:", total)
```

```output
вишня
айва
всего: 11
```

Разбор: `receive` прибавляет к текущему остатку, а `get(name, 0)` обслуживает
случай нового товара. `ship` не даёт остатку уйти в минус: `max(..., 0)`
отсекает отрицательный результат. Товар «айва» ранее не встречался, поэтому
`get` вернул `0`, и в словаре появился ключ со значением `0`. Словарь во время
итогового обхода не меняется, поэтому `RuntimeError` не возникает.

## 10. Почему словарь быстрее списка пар {#sol-ch17-10}

Список пар не знает, где лежит нужное имя: единственный способ — сравнивать
по очереди. Число сравнений растёт вместе с числом записей. Словарь хранит
ключи в хеш-таблице: по ключу вычисляется хеш, который сразу указывает на
нужную ячейку, поэтому число шагов почти не зависит от размера словаря.

```python exec
catalog = [("яблоко", 90), ("банан", 120), ("вишня", 350), ("груша", 200), ("слива", 150)]
checked = 0
for name, price in catalog:
    checked = checked + 1
    if name == "слива":
        break
print("список пар: сравнений", checked)

prices = {"яблоко": 90, "банан": 120, "вишня": 350, "груша": 200, "слива": 150}
print("словарь: обращений", 1, "—", prices["слива"])
```

```output
список пар: сравнений 5
словарь: обращений 1 — 150
```

В списке из пяти пар нужная оказалась последней — понадобилось пять сравнений.
Словарю достаточно одного обращения по ключу. В среднем поиск по хеш-таблице
занимает постоянное время, тогда как поиск перебором — время, пропорциональное
длине списка.

## Ответы на вопросы для самопроверки

1. Отображение хранит соответствие «ключ → значение» и даёт доступ по ключу;
   последовательность хранит элементы в порядке позиций и даёт доступ по
   индексу. Словарь — отображение.
2. Ключи уникальны, потому что словарь хранит соответствие, а не список;
   повторный ключ в литерале заменяет значение, оставляя ключ на прежнем месте.
3. `KeyError` обнаруживает отсутствие сразу и в конкретном месте; `None` легко
   спутать с законным значением и пронести дальше по программе.
4. `in` проверяет ключи; наличие значения проверяется проходом по
   `d.values()` или обратной проверкой `value in d.values()`.
5. `setdefault` создаёт ключ при отсутствии и возвращает действующее значение;
   `get` только читает и словарь не меняет.
6. Обход опирается на внутреннее состояние хеш-таблицы; изменение размера его
   сбивает. Безопасно: обходить `list(d)` или строить новый словарь.
7. Кортеж короче, но смысл полей держится на порядке; словарь называет поля,
   позволяет добавлять и удалять их без сдвига остальных.
