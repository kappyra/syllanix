# Решения к главе 18

Главное в этой главе — не запомнить названия функций, а научиться мысленно
рисовать стрелки: имя → объект. Тогда результат становится предсказуемым до
запуска.

## 1. Прогнозирование вывода {#sol-ch18-01}

```python exec
a = [1, 2]
b = a
b = b + [3]
print(a)
print(b)
```

```output
[1, 2]
[1, 2, 3]
```

`b = b + [3]` создаёт новый список и связывает с ним `b`; список `a` остаётся
прежним объектом. Если заменить эту строку на `b.append(3)`, изменится общий
объект, и `a` тоже станет `[1, 2, 3]`:

```python exec
a = [1, 2]
b = a
b.append(3)
print(a)
```

```output
[1, 2, 3]
```

Разница между «создать новый объект» и «изменить существующий» — ключ ко всей
главе.

## 2. is или == {#sol-ch18-02}

```python exec
x = [1, 2]
y = [1, 2]
print(x == y)
print(x is y)
```

```output
True
False
```

Списки равны по значению, но это разные объекты. С числами интереснее:
CPython кеширует небольшие целые числа, поэтому два имени могут указывать на
один объект, а для больших значений — нет.

```python exec
x = 100
y = int("100")
print(x is y, x == y)
x = 1000
y = int("1000")
print(x is y, x == y)
```

```output
True True
False True
```

Кеш малых чисел — особенность CPython, а не гарантия языка: диапазон кеша и
сам факт кеширования вправе измениться. Для сравнения чисел и строк всегда
используйте `==`, а `is` — только там, где нужна идентичность, и практически
всегда — для `None`.

## 3. Функция портит аргумент {#sol-ch18-03}

Причина: `numbers` внутри функции — второе имя того же списка, что и `data`
снаружи. Удаление элементов меняет общий объект. Кроме того, удаление во
время обхода списка пропускает элементы — поэтому «баг» ещё и логический.

```python exec
def positive_buggy(numbers):
    for number in numbers:
        if number < 0:
            numbers.remove(number)
    return numbers


data = [3, -1, 4, -2]
print(positive_buggy(data))
print(data)
```

```output
[3, 4]
[3, 4]
```

Исправление — строить новый список и не трогать входной:

```python exec
def positive(numbers):
    result = []
    for number in numbers:
        if number >= 0:
            result.append(number)
    return result


data = [3, -1, 4, -2]
print(positive(data))
print(data)
```

```output
[3, 4]
[3, -1, 4, -2]
```

## 4. Три способа скопировать список {#sol-ch18-04}

```python exec
original = [1, 2, 3]
a = original.copy()
b = original[:]
c = list(original)
print(a == original, b == original, c == original)
print(a is original, b is original, c is original)
a.append(4)
print(original, a)
```

```output
True True True
False False False
[1, 2, 3] [1, 2, 3, 4]
```

Все три способа дают поверхностную копию: новый список с теми же элементами.
Для плоского списка этого достаточно, чтобы копия была независимой.

## 5. Поверхностная ловушка {#sol-ch18-05}

```python exec
matrix = [[1, 2], [3, 4]]
clone = matrix.copy()
clone[1].append(99)
print(matrix)
print(clone)
print(matrix[1] is clone[1])
```

```output
[[1, 2], [3, 4, 99]]
[[1, 2], [3, 4, 99]]
True
```

Вложенный список общий, поэтому изменение через копию видно в оригинале.
Глубокое копирование убирает совпадение:

```python exec
import copy

matrix = [[1, 2], [3, 4]]
deep = copy.deepcopy(matrix)
deep[0].append(7)
print(matrix)
print(deep)
```

```output
[[1, 2], [3, 4]]
[[1, 2, 7], [3, 4]]
```

## 6. Вложенный словарь {#sol-ch18-06}

```python exec
user = {"имя": "Анна", "оценки": [4, 5]}
shallow = dict(user)
shallow["оценки"].append(3)
print(user)
print(shallow)
```

```output
{'имя': 'Анна', 'оценки': [4, 5, 3]}
{'имя': 'Анна', 'оценки': [4, 5, 3]}
```

`dict(user)` создаёт новый словарь, но значение по ключу `оценки` — та же
ссылка на список. С глубоким копированием:

```python exec
import copy

user = {"имя": "Анна", "оценки": [4, 5]}
deep = copy.deepcopy(user)
deep["оценки"].append(3)
print(user)
print(deep)
```

```output
{'имя': 'Анна', 'оценки': [4, 5]}
{'имя': 'Анна', 'оценки': [4, 5, 3]}
```

Различие объясняется вложенной структурой: поверхностная копия копирует
только верхний уровень, глубокое копирование — все уровни.

## 7. Значение по умолчанию {#sol-ch18-07}

```python exec
def log(message, history=None):
    if history is None:
        history = []
    history.append(message)
    return history


print(log("старт"))
print(log("шаг 1"))
shared = []
print(log("а", shared))
print(log("б", shared))
```

```output
['старт']
['шаг 1']
['а']
['а', 'б']
```

`None` — признак «аргумент не передан». Явно переданный список продолжает
накапливать записи, что и требовалось.

## 8. Копия внутри функции {#sol-ch18-08}

```python exec
def without_duplicates(items):
    result = []
    for item in items:
        if item not in result:
            result.append(item)
    return result


data = ["а", "б", "а", "в", "б"]
print(without_duplicates(data))
print(data)
```

```output
['а', 'б', 'в']
['а', 'б', 'а', 'в', 'б']
```

Функция строит новый список и не меняет входной. Обратите внимание на цену:
проверка `item not in result` — линейный поиск, поэтому для больших списков
такой способ медленный. Вы уже познакомились с множествами в главе 16;
проверку через `set` можно использовать и здесь.

## 9. Резервная копия настроек {#sol-ch18-09}

```python exec
import copy


def snapshot(settings):
    return copy.deepcopy(settings)


settings = {"темы": ["светлая"], "язык": "ru"}
backup = snapshot(settings)
backup["темы"].append("тёмная")
print(settings)
print(backup)
print(settings["темы"] is backup["темы"])
```

```output
{'темы': ['светлая'], 'язык': 'ru'}
{'темы': ['светлая', 'тёмная'], 'язык': 'ru'}
False
```

`dict(settings)` здесь не подходит: он создаёт новый словарь, но список
`темы` остаётся общим, и добавление темы в копию изменило бы оригинал.
`deepcopy` копирует и вложенный список, поэтому резервная копия независима.

## 10. Где алиасинг полезен {#sol-ch18-10}

Полезен алиасинг, когда несколько частей программы должны видеть одни и те же
изменения: общий журнал, очередь задач, кэш.

```python exec
def record(event, journal):
    journal.append(event)


journal = []
alias = journal
record("старт", journal)
record("финиш", alias)
print(journal)
print(alias is journal)
```

```output
['старт', 'финиш']
True
```

Опасен алиасинг, когда имена считают независимыми: «резервная копия»,
которая меняется вместе с оригиналом, или функция, очищающая чужой список.

```python exec
def clear_all(items):
    items.clear()


data = [1, 2, 3]
alias = data
clear_all(alias)
print(data)
```

```output
[]
```

Мораль: алиасинг — инструмент, а не дефект. Дефект начинается там, где
независимость предполагалась, но не была обеспечена копией.

## Ответы на вопросы для самопроверки

1. Присваивание копирует ссылку; проверить можно сравнением `a is b` после
   `b = a` для изменяемого объекта.
2. `==` сравнивает значения, `is` — идентичность объектов. `is` уместен для
   `None` и там, где нужна именно одна и та же сущность.
3. Оба имени указывают на один изменяемый объект, поэтому изменение объекта
   видно через любое имя.
4. Поверхностное копирование создаёт новый верхний уровень и разделяет
   вложенные объекты; глубокое копирует все уровни рекурсивно.
5. Значение по умолчанию вычисляется при определении функции и хранится в её
   объекте; поэтому изменяемый объект переиспользуется между вызовами.
6. Кортеж неизменяем по ссылкам, но объект, на который ссылается элемент,
   может быть изменяемым; его изменение кортеж не запрещает.
7. Глубокое копирование не нужно, если структура плоская, если объект дальше
   не меняется или если копия нужна только на уровне верхнего слоя.
