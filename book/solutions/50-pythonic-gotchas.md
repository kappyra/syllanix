# Решения к главе 50

Проверяйте себя запуском: ловушки этой главы удобнее увидеть, чем
запомнить. Особенно это касается `is`, значений по умолчанию и float.

## 1. Прогнозирование `is` и `==` {#sol-ch50-01}

```python exec
a = "python"
b = "".join(["py", "thon"])
print(a == b)
print(a is b)
```

```output
True
False
```

Сравнение `==` истинно: строки одинаковые. Сравнение `is` ложно: `b`
собрана во время выполнения, поэтому это другой объект. Литерал `"python"`
интернирован, а результат `join` — нет. Полагаться на идентичность строк
нельзя.

## 2. Исправление изменяемого значения по умолчанию {#sol-ch50-02}

```python exec
def collect(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

print(collect(1))
print(collect(2))
print(collect(3))
```

```output
[1]
[2]
[3]
```

`None` служит признаком «аргумент не передан», а новый список создаётся
внутри вызова. Каждый вызов получает собственный список, накопления между
вызовами больше нет.

## 3. enumerate вместо счётчика {#sol-ch50-03}

```python exec
words = ["раз", "два", "три"]
for position, word in enumerate(words, start=1):
    print(position, word)
```

```output
1 раз
2 два
3 три
```

`enumerate` выдаёт пару «позиция, элемент» — счётчик не нужен.
Параметр `start=1` избавляет от прибавления единицы вручную.

## 4. zip и строгая проверка {#sol-ch50-04}

Без `strict` лишние элементы молча отбрасываются.

```python exec
names = ["a", "b", "c"]
ages = [30, 25]
print(list(zip(names, ages)))
```

```output
[('a', 30), ('b', 25)]
```

С `strict=True` несовпадение длин — ошибка.

```python exec expect-error
names = ["a", "b", "c"]
ages = [30, 25]
print(list(zip(names, ages, strict=True)))
```

```output
ValueError: zip() argument 2 is shorter than argument 1
```

Если разная длина означает дефект данных, `strict` лучше: ошибка видна
сразу, а не превращается в тихую потерю элемента.

## 5. dict.get для подсчёта {#sol-ch50-05}

```python exec
text = "раз два раз три раз"
counts = {}
for word in text.split():
    counts[word] = counts.get(word, 0) + 1
print(counts)
```

```output
{'раз': 3, 'два': 1, 'три': 1}
```

`get` возвращает 0 для нового слова, а дальше идёт обычное сложение.
Порядок ключей в словаре соответствует первому появлению слова, поэтому
вывод предсказуем.

## 6. for ... else {#sol-ch50-06}

```python exec
numbers = [2, 4, 6]
for number in numbers:
    if number % 2:
        print("первое нечётное:", number)
        break
else:
    print("все чётные")
numbers = [2, 5, 6]
for number in numbers:
    if number % 2:
        print("первое нечётное:", number)
        break
else:
    print("все чётные")
```

```output
все чётные
первое нечётное: 5
```

Ветвь `else` выполняется, только если цикл дошёл до конца без `break`.
Переменная-флаг не нужна: намерение выражено структурой цикла.

## 7. Запятая в кортеже {#sol-ch50-07}

Запятая после вызова создаёт кортеж из одного элемента.

```python exec
def one():
    return [1]

value = one(),
print(type(value).__name__, len(value))
value = one()
print(type(value).__name__, value)
```

```output
tuple 1
list [1]
```

Кортеж создаёт запятая, а не скобки. Чтобы получить список, уберите
запятую после вызова: `value = one()`. Если же кортеж нужен, пишите его
явно и с запятой внутри: `(one(),)`.

## 8. Сравнение float {#sol-ch50-08}

```python exec
from math import isclose
from decimal import Decimal

print(0.1 + 0.2 == 0.3)
print(isclose(0.1 + 0.2, 0.3))
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))
```

```output
False
True
True
```

Прямое сравнение ложно: сумма хранится как `0.30000000000000004`.
`isclose` сравнивает с допуском, а `Decimal` хранит десятичные дроби
точно. Для денег выбирают `Decimal` или целые единицы (копейки), а не
округление float.

## 9. Сортировка без учёта регистра {#sol-ch50-09}

```python exec
words = ["Zebra", "apple", "Banana"]
print(sorted(words))
print(sorted(words, key=str.lower))
print(sorted(["ёж", "арбуз", "Яблоко"]))
```

```output
['Banana', 'Zebra', 'apple']
['apple', 'Banana', 'Zebra']
['Яблоко', 'арбуз', 'ёж']
```

Без ключа сортировка идёт по кодовым точкам: заглавные раньше строчных.
С `key=str.lower` регистр не влияет на порядок. Русские слова
сортировались по кодовым точкам: `ё` оказалась после `я`, а заглавная `Я`
раньше строчных. Для алфавитного порядка нужна локаль и
`locale.strxfrm`.

## 10. Мини-задача: питоническая сводка {#sol-ch50-10}

```python exec
def summary(words):
    counts = {word: words.count(word) for word in dict.fromkeys(words)}
    repeated = [word for word, count in counts.items() if count > 1]
    return counts, repeated

counts, repeated = summary(["раз", "два", "раз", "три", "раз"])
print(counts)
print(repeated)
```

```output
{'раз': 3, 'два': 1, 'три': 1}
['раз']
```

`dict.fromkeys(words)` перебирает слова в порядке появления и убирает
повторы, поэтому словарное включение даёт предсказуемый порядок ключей.
Включение с условием отбирает повторяющиеся слова. Такой код читается
как формулировка задачи: «словарь слово-количество, затем слова с
количеством больше одного».

## Ответы на вопросы для самопроверки

1. Питонический код следует идиомам языка и читается без разбора
   деталей; работающий код может быть запутанным и хрупким.
2. Принцип «ошибки не должны замалчиваться без явного намерения»: пустой
   `except` скрывает проблему.
3. Значение по умолчанию вычисляется один раз при создании функции и
   хранится в её объекте; изменяемый объект сохраняет изменения.
4. `is` проверяет идентичность объекта, `==` — равенство значений. У
   чисел и строк идентичность зависит от реализации, поэтому нужен `==`.
5. CPython кэширует малые целые от −5 до 256; 256 берётся из кэша, а для
   257 создаётся новый объект.
6. Интернирование — повторное использование объекта для одинаковых
   строк; литералы интернируются, строки времени выполнения — нет, на это
   нельзя опираться.
7. Скобки не создают кортеж; его создаёт запятая, поэтому `(1)` — число.
8. Двоичное представление не хранит десятичные дроби точно, поэтому
   сравнение через `==` даёт ложь при визуально равных числах.
9. Когда идиома усложняет чтение: вложенные включения, скрытые побочные
   эффекты, цепочки `and`/`or` вместо явной проверки.
