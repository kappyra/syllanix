# Решения к главе 11

Отладка проверяется практикой: важно не знать названия инструментов, а
уметь получить с их помощью ответ на конкретный вопрос.

## 1. Порядок кадров {#sol-ch11-01}

```python exec
import traceback

def level_three(value):
    return 100 / value

def level_two(value):
    return level_three(value) + 1

def level_one(value):
    return level_two(value) * 2

try:
    level_one(0)
except ZeroDivisionError as error:
    for frame in traceback.extract_tb(error.__traceback__):
        print(frame.name)
```

```output
<module>
level_one
level_two
level_three
```

Порядок совпадает с текстом трассировки: сверху вниз от самого раннего
кадра к самому позднему. `<module>` — код верхнего уровня, затем
вызывающие функции, последняя строка — место сбоя.

## 2. Чтение отчёта {#sol-ch11-02}

Сбой произошёл в функции `ratio`, в строке 5: там выполняется
`total / count`. Вызвал её код верхнего уровня в строке 12, передав
`count = 0`. Исправление — проверить делитель до деления:

```python exec
def ratio(total, count):
    if count == 0:
        return None
    return total / count

print(ratio(10, 2))
print(ratio(10, 0))
```

```output
5.0
None
```

Проверка вернула `None` вместо значения: вызывающему коду придётся решить,
что делать с отсутствием результата. Это лучше, чем падение, но контракт
функции нужно описать в docstring.

## 3. Отладка через print {#sol-ch11-03}

```python exec
def average(total, count):
    print("total =", total, "count =", count)
    if count == 0:
        print("дефект: count равен нулю")
        return 0
    return total / count

print(average(10, 4))
print(average(10, 0))
```

```output
total = 10 count = 4
2.5
total = 10 count = 0
дефект: count равен нулю
0
```

Отладочные строки показывают входные значения перед решением. После
исправления их убирают: они засоряют вывод, замедляют работу и раскрывают
внутренние данные. Если такая информация нужна постоянно, её место — в
журнале уровня `DEBUG`.

## 4. Уровни журнала {#sol-ch11-04}

```python exec
import logging
import sys

logging.basicConfig(stream=sys.stdout, level=logging.WARNING,
                    format="%(levelname)s %(message)s")
log = logging.getLogger("check")

log.debug("значения на входе")
log.info("обработка началась")
log.warning("файл не найден, взяты значения по умолчанию")
log.error("расчёт не удался")
```

```output
WARNING файл не найден, взяты значения по умолчанию
ERROR расчёт не удался
```

Появились только сообщения уровня `WARNING` и выше. `DEBUG` и `INFO` ниже
установленного порога, поэтому отброшены. Обратите внимание на формат
`%(levelname)s %(message)s`: без него в выводе не было бы видно уровня.

## 5. Выбор уровня {#sol-ch11-05}

1. Запуск и чтение настроек — `INFO`: значимое штатное событие.
2. Значение больше ожидаемого, обработка продолжилась — `WARNING`:
   неожиданность, которую программа пережила.
3. Платёж отклонён банком — `ERROR`: операция не выполнена.
4. Недоступна база данных, без которой работа невозможна — `CRITICAL`:
   продолжать нельзя.
5. Промежуточная сумма на каждом шаге — `DEBUG`: подробность, нужная
   только при разборе.

Проверить классификацию можно запуском; важно, что уровень выбирается по
последствиям события, а не по настроению разработчика.

```python exec
import logging
import sys

logging.basicConfig(stream=sys.stdout, level=logging.DEBUG,
                    format="%(levelname)s %(message)s")
log = logging.getLogger("order")
log.debug("проверяем остаток на складе: 3")
log.info("заказ принят: номер 17")
log.warning("срок доставки больше обычного")
log.error("оплата отклонена банком")
```

```output
DEBUG проверяем остаток на складе: 3
INFO заказ принят: номер 17
WARNING срок доставки больше обычного
ERROR оплата отклонена банком
```

## 6. Команды отладчика {#sol-ch11-06}

Последовательность команд: `p amount` — посмотреть значение, `n` —
выполнить текущую строку без захода внутрь вызовов, `q` — выйти. Если
нужно исследовать вызов изнутри, вместо `n` используют `s` (step): она
входит в вызываемую функцию и останавливается на её первой строке. `n`
(длижайшая по смыслу «следующая») оставляет выполнение в текущем кадре.

Дополнительно полезны `l` для просмотра окружающих строк, `pp` для
подробного вывода значения и `b` для точки останова, если сеанс длинный.

## 7. Минимальный пример {#sol-ch11-07}

Сначала воспроизводим дефект в большом расчёте, затем выписываем только
функцию и два вызова с теми же аргументами. Если дефект сохраняется,
лишние части кода не нужны для его поиска.

Ошибочная версия считает скидку как `price * percent`, то есть умножает цену
на 15, а не на 0,15:

```python exec
def final_price(price, percent):
    discount = price * percent
    return price - discount

print(final_price(1000, 15))
print(final_price(100, 15))
```

```output
-14000
-1400
```

В минимальном примере сразу видно, что скидка `15000` больше цены `1000`:
процент не переведён в долю. Исправление — делить на 100 (или умножать на
`percent / 100`):

```python exec
def final_price(price, percent):
    discount = price * percent / 100
    return price - discount

print(final_price(1000, 15))
print(final_price(100, 15))
```

```output
850.0
85.0
```

Теперь `1000 * 15 / 100 = 150` — скидка, а итог `850.0`; для `100` получается
`85.0`. Сравнение двух версий на одних и тех же вызовах показывает, что дело
именно в формуле скидки. Минимальный
пример удобен ещё и тем, что его можно превратить в проверку при
исправлении.

## 8. print или логирование {#sol-ch11-08}

В первой ситуации подходит отладка через print или отладчик: обратная
связь нужна немедленно, код под рукой, а вывод можно удалить сразу после
ответа. Во второй ситуации нужно логирование: процесс идёт на сервере,
раз в неделю, без интерактивного доступа. Сообщения должны сохраняться
заранее настроенными, с уровнями и контекстом, иначе к моменту разбора
уже нечего смотреть.

Общее правило: print — инструмент здесь и сейчас, логирование —
инструмент для истории. Отладчик — инструмент для состояния в конкретной
точке.

## 9. Дефект в цикле {#sol-ch11-09}

```python exec
def sum_to(n):
    total = 0
    for number in range(1, n):
        total += number
    return total

print(sum_to(5))
print(sum_to(10))
```

```output
10
45
```

Для `n = 5` сумма должна быть `1 + 2 + 3 + 4 + 5 = 15`, а получено 10:
пропущено последнее слагаемое. Причина в `range(1, n)`: правый конец
диапазона не включается, поэтому `n` в сумму не попадает. Исправление —
`range(1, n + 1)`.

```python exec
def sum_to(n):
    total = 0
    for number in range(1, n + 1):
        total += number
    return total

print(sum_to(5))
print(sum_to(10))
```

```output
15
55
```

Проверка на границе — обязательный шаг: дефекты такого рода не видны на
середине диапазона.

## 10. Мини-задача: журнал перевода {#sol-ch11-10}

```python exec
import logging
import sys

logging.basicConfig(stream=sys.stdout, level=logging.INFO,
                    format="%(levelname)s %(message)s")
log = logging.getLogger("payments")

def transfer(balance, amount):
    log.info("перевод: balance=%s amount=%s", balance, amount)
    if amount > balance:
        log.error("недостаточно средств: нужно %s, доступно %s", amount, balance)
        return None
    return balance - amount

print(transfer(100, 30))
print(transfer(100, 300))
```

```output
INFO перевод: balance=100 amount=30
70
INFO перевод: balance=100 amount=300
ERROR недостаточно средств: нужно 300, доступно 100
None
```

Функция записывает вход на уровне `INFO`, а отказ — на уровне `ERROR` с
обоими значениями. Такой журнал отвечает на вопрос «почему отказ», не
требуя повторного запуска. Обратите внимание: сообщения передаются с
параметрами через `%s`, а не склеиваются заранее, — это принятая практика
логирования.

## Ответы на вопросы для самопроверки

1. Заголовок означает, что последний вызов записан в конце; кадры читают
   сверху вниз от раннего к позднему, а последний кадр — место сбоя.
2. Сбой происходит там, где операция невозможна, а причина формируется
   раньше — в вызывающем коде, который подготовил данные.
3. print даёт сиюминутную обратную связь и живёт до удаления строки;
   логирование сохраняет историю событий с уровнями для будущего разбора.
4. Уровни позволяют отбрасывать лишнее: сообщения ниже установленного
   уровня не записываются, поэтому журнал остаётся обозримым.
5. `n` выполняет строку целиком и остаётся в текущем кадре; `s` входит
   внутрь вызываемой функции и останавливается на её первой строке.
6. `breakpoint()` останавливает процесс: в неинтерактивном окружении он
   приведёт к зависанию, а в рабочем коде — к неожиданной остановке.
7. Шаг проверки: гипотеза формулируется как предсказание, которое можно
   подтвердить или опровергнуть наблюдением.
