# Решения к главе 49

В задачах про стиль нет единственно правильного ответа, но есть плохие и
хорошие решения. Сверяйте не только текст программы, но и объяснение: важно
понимать, какое правило нарушено и зачем оно существует.

## 1. Нарушения оформления {#sol-ch49-01}

В исходном фрагменте три нарушения: нет пробела после запятой в списке
параметров, нет пробелов вокруг оператора присваивания и вокруг знака
умножения.

```python exec
def area(width, height):
    result = width * height
    return result

print(area(3, 4))
```

```output
12
```

Поведение не изменилось: PEP 8 нормирует оформление, а не смысл. Разница
только в том, что исправленный вариант читается с первого взгляда.

## 2. Длинная строка {#sol-ch49-02}

Строку делят на части и собирают соседние литералы: Python склеивает их
автоматически, если между ними нет ничего, кроме пробелов и переносов в
скобках.

```python exec
count = 3
total = 750
discount = 75
message = (
    f"Товаров: {count}, сумма без скидки: {total}, "
    f"скидка: {discount}, к оплате: {total - discount} рублей"
)
print(message)
```

```output
Товаров: 3, сумма без скидки: 750, скидка: 75, к оплате: 675 рублей
```

Скобки вокруг выражения обязательны: без них перенос внутри строкового
литерала стал бы частью строки и добавил лишние пробелы. Другой вариант —
вынести части в отдельные переменные с осмысленными именами.

## 3. Именование переменных {#sol-ch49-03}

```python exec
price = 250
count = 3
discount_percent = 10
total = price * count
discount = total * discount_percent // 100
print(total - discount)
```

```output
675
```

Имена `a`, `b`, `c` не сообщают ролей: по ним нельзя понять, что именно
умножается и на что. Новые имена называют смысл, и формула читается как
описание задачи.

## 4. Формы записи {#sol-ch49-04}

`max_retries` — константа в нижнем регистре; по форме это `snake_case`, и если
значение не меняется, по соглашению его пишут как `MAX_RETRIES`. `HttpClient`
— класс, `PascalCase` выбран верно. `parse_config` — функция, `snake_case`
верен. `DEFAULT_TIMEOUT` — константа, `UPPER_CASE` верен. `_cache` — внутреннее
имя модуля или класса, ведущее подчёркивание сообщает, что это деталь
реализации. `OrderError` — класс исключения: `PascalCase` и суффикс `Error`,
как принято в стандартной библиотеке.

## 5. Плохие имена {#sol-ch49-05}

`data` не говорит, какие именно данные и в какой форме; в контексте заказа
лучше `order_items`. `tmp` описывает роль («временное»), а не содержимое;
`previous_total` объясняет, что хранится. `process` — глагол без объекта:
непонятно, что обрабатывается; `normalize_phone` называет операцию.
`flag` не сообщает, что означает истина; `is_paid` читается как утверждение.
`l` — односимвольное имя, которое легко спутать с единицей; линтер помечает
его правилом E741, а замена на `line_total` снимает и неоднозначность, и
замечание.

## 6. Комментарий о причине {#sol-ch49-06}

Комментарий «прибавляем единицу к счётчику» пересказывает код и не нужен.
Пояснение требуется, когда у прибавления есть причина, не выводимая из кода:

```python
# Считаем попытки с единицы: ноль зарезервирован под «попыток не было».
counter += 1
```

Смысл в том, что читатель не должен угадывать, почему счёт начинается не с
нуля. Такой комментарий переживёт рефакторинг: он объясняет решение, а не
строку.

## 7. Docstring {#sol-ch49-07}

```python exec
def ticket_price(age, base=600):
    """Вернуть цену билета для указанного возраста.

    Args:
        age: возраст посетителя в годах.
        base: базовая цена билета в рублях.

    Returns:
        Цена билета в рублях; для возраста до 18 лет — половина базовой.
    """
    if age < 18:
        return base // 2
    return base

print(ticket_price(12))
print(ticket_price(30))
print(ticket_price.__doc__.splitlines()[0])
```

```output
300
600
Вернуть цену билета для указанного возраста.
```

Первая строка самостоятельна: её видно в подсказке редактора без остального
текста. Разделы `Args` и `Returns` описывают параметры и результат так, чтобы
читателю не приходилось читать тело функции.

## 8. Магические числа {#sol-ch49-08}

```python exec
LATE_FEE_PERCENT = 5


def late_fee(amount):
    return amount + amount * LATE_FEE_PERCENT // 100

print(late_fee(200))
```

```output
210
```

Число `5` получило имя: теперь видно, что это процент пени, а не случайная
величина. Значение `210` совпадает с исходным поведением, поэтому замена
безопасна. Если правило изменится, достаточно поправить константу в одном
месте.

## 9. Разбор сообщений линтера {#sol-ch49-09}

Первое сообщение — неиспользуемый импорт `os`: модуль подключён, но нигде не
применяется. Его удаляют. Второе — имя `l`, которое легко спутать с единицей;
его переименовывают. Третье — сравнение с `True`: вместо `flag == True`
достаточно `if flag:`.

```python exec
def check(flag):
    if flag:
        return "включено"
    return "выключено"

print(check(True))
```

```output
включено
```

Линтер указывает не на «плохой вкус», а на места, где код может быть понят
неверно или содержит лишнюю работу.

## 10. Мини-задача: привести модуль в порядок {#sol-ch49-10}

```python exec
"""Расчёты для заказа."""

DISCOUNT_STEP = 100


def order_total(price, count, discount_percent=0):
    """Вернуть итог заказа в целых рублях.

    Args:
        price: цена единицы товара в рублях.
        count: количество единиц.
        discount_percent: скидка в процентах от суммы.

    Returns:
        Итог заказа после скидки.
    """
    total = price * count
    discount = total * discount_percent // DISCOUNT_STEP
    return total - discount

print(order_total(250, 3, 10))
```

```output
675
```

Что изменилось: неиспользуемый импорт удалён; однобуквенные имена заменены
осмысленными; `discount = 0` записан без лишних пробелов; магическое число
`100` стало константой `DISCOUNT_STEP`; появился docstring; комментарий,
пересказывающий код, убран, потому что смысл теперь виден из имён. Результат
для `(250, 3, 10)` остался `675` — значит, переработка не изменила поведение.

## Ответы на вопросы для самопроверки

1. Стиль снижает стоимость чтения, ревью и сопровождения, а также уменьшает
   шум в истории изменений — это измеримая инженерная польза.
2. PEP 8 нормирует оформление и договорённости об именах; интерпретатор не
   проверяет эти правила, поэтому нарушение не мешает программе работать.
3. Форматтер приводит оформление к единому виду, линтер ищет подозрительные
   конструкции и нарушения правил, которые нельзя исправить автоматически.
4. mypy сверяет значения с аннотациями типов; он не проверяет логику и
   поведение, поэтому тесты он не заменяет.
5. Переменные и функции — `snake_case`, классы — `PascalCase`, константы —
   `UPPER_CASE`, внутренние имена — с ведущим подчёркиванием.
6. Перекрытие ломает стандартную функцию, и ошибка проявляется в другом месте,
   где её трудно связать с причиной.
7. Полезный комментарий объясняет причину решения; бесполезный пересказывает
   код или устаревает.
8. Краткое назначение, параметры, возвращаемое значение; при необходимости —
   исключения.
9. Магическое число — константа без объяснения смысла; её заменяют именованной
   константой в начале модуля.
10. Массовая правка оформления создаёт шум в истории и конфликты в ветках;
    стиль — повод договориться, а не переписать весь проект.
