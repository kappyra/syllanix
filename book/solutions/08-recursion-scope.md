# Решения к главе 8

В задачах про стек и области видимости полезно рисовать схему на бумаге: три
прямоугольника кадров или три уровня имён. Решения ниже показывают, что должно
получиться.

## 1. Порядок вывода {#sol-ch08-01}

```python exec
def first():
    print("первая")

def second():
    first()
    print("вторая")

second()
```

```output
первая
вторая
```

`second` начинает работу, вызывает `first`, тот печатает строку и завершается.
Только после этого управление возвращается в `second`, и печатается `вторая`.
Сначала завершается самый глубокий вызов — это и есть работа стека.

## 2. Кадры независимы {#sol-ch08-02}

```python exec
def step(n):
    n = n * 10
    print(n)

step(1)
step(2)
```

```output
10
20
```

Каждый вызов создаёт свой кадр: в первом параметр `n` равен `1`, во втором —
`2`. Первый кадр снимается после возврата, поэтому второе значение не зависит
от первого.

## 3. Три области видимости {#sol-ch08-03}

```python exec
value = "глобальное"

def outer():
    value = "объемлющее"

    def inner():
        value = "локальное"
        print(value)

    inner()
    print(value)

outer()
print(value)
```

```output
локальное
объемлющее
глобальное
```

`inner` создаёт собственное имя `value`, поэтому первое `print` видит локальное
значение. В `outer` своё имя `value`, и второе `print` видит объемлющее.
Третье `print` стоит на верхнем уровне, вне функций, поэтому видит глобальное
значение.

## 4. Чтение из объемлющей области {#sol-ch08-04}

```python exec
def outer():
    message = "готово"

    def inner():
        print(message)

    inner()

outer()
```

```output
готово
```

Параметр не нужен, потому что `inner` определена внутри `outer` и видит имена
её области. Поиск имени `message` начинается с локальной области `inner`, там
его нет, поэтому поднимается на уровень выше — в кадр `outer`, где имя есть.
Важно, что доступ идёт только на чтение: присваивание создало бы в `inner`
новое локальное имя и не изменило `outer`.

## 5. global {#sol-ch08-05}

Без объявления функция считает `total` локальным именем, потому что присваивает
ему значение. Тогда чтение `total += 1` происходит до того, как имя связано, и
возникает `UnboundLocalError`. Исправление — объявить имя глобальным:

```python exec
total = 0

def add():
    global total
    total += 1
    return total

add()
add()
add()
print(total)
```

```output
3
```

Работает, но обратите внимание: теперь результат зависит от того, сколько раз
вызвана функция. Более предсказуемый вариант — возвращать новое значение и
хранить его в вызывающем коде.

## 6. Исправление рекурсии {#sol-ch08-06}

В функции нет базового случая: `countdown(0)` вызовет `countdown(-1)`, тот
дальше, и так до `RecursionError`. Нужна остановка:

```python exec
def countdown(n):
    print(n)
    if n == 0:
        return
    countdown(n - 1)

countdown(3)
```

```output
3
2
1
0
```

Базовый случай — `n == 0`: функция печатает ноль и возвращается, не порождая
нового вызова.

## 7. Факториал {#sol-ch08-07}

```python exec
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

print(factorial(0))
print(factorial(1))
print(factorial(6))
```

```output
1
1
720
```

Базовый случай `n <= 1` покрывает и `0`, и `1`: факториал обоих равен единице.
`6! = 720`. Каждый вызов уменьшает аргумент на единицу, поэтому рекурсия
завершается.

## 8. Сумма цифр {#sol-ch08-08}

```python exec
def digit_sum(n):
    if n < 10:
        return n
    return n % 10 + digit_sum(n // 10)

print(digit_sum(1234))
print(digit_sum(9))
```

```output
10
9
```

Для `1234`: `4 + digit_sum(123)` и так далее до однозначного числа. Для `9`
сразу срабатывает базовый случай, и возвращается само число. Сумма цифр
`1234` равна `1 + 2 + 3 + 4 = 10`.

## 9. Предел рекурсии {#sol-ch08-09}

Функция `total(n)` вызывает себя с `n - 1`, но не имеет базового случая.
Аргумент уходит в отрицательные числа, и рекурсия никогда не останавливается —
в итоге возникает `RecursionError: maximum recursion depth exceeded`.
Исправление циклом:

```python exec
def total(n):
    result = 0
    for i in range(1, n + 1):
        result += i
    return result

print(total(5))
```

```output
15
```

Цикл не расходует стек: все итерации выполняются в одном кадре, поэтому глубина
не растёт. Сумма чисел от 1 до 5 равна `15`.

## 10. Мини-задача: Евклид {#sol-ch08-10}

```python exec
def gcd(a, b):
    if b == 0:
        return a
    return gcd(b, a % b)

print(gcd(84, 36))
print(gcd(17, 5))
```

```output
12
1
```

Второй ответ — `1`: числа 17 и 5 взаимно простые, поэтому их наибольший общий
делитель равен единице. Рекурсия завершается потому, что остаток от деления
строго меньше делителя: последовательность вторых аргументов убывает и рано или
поздно становится нулём. Для `84` и `36` цепочка такая:
`(84, 36) → (36, 12) → (12, 0)`, ответ `12`.

## Ответы на вопросы для самопроверки

1. Стек вызовов хранит активные вызовы; завершается всегда последний начатый,
   поэтому порядок обратный.
2. Параметры, локальные имена и точку возврата конкретного вызова.
3. Потому что у каждого вызова свой кадр, а локальные имена принадлежат кадру,
   а не функции.
4. Локальная, объемлющая, глобальная, встроенная; поиск идёт изнутри наружу.
5. Глобальная область — имена конкретного файла на верхнем уровне; встроенная —
   имена, доступные всегда (`print`, `int`).
6. Она позволяет функции переприсвоить глобальное имя; применяют редко, потому
   что функция начинает зависеть от внешнего состояния.
7. Базовый случай — условие возврата без нового вызова; без него рекурсия
   бесконечна и завершается `RecursionError`.
8. Потому что конкретное число задаёт реализация (в CPython около 1000), а не
   спецификация языка.
9. Когда задача естественно сводится к меньшей копии себя: обход дерева, разбор
   вложенных структур, алгоритмы «разделяй и властвуй».
