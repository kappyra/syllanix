# Решения к главе 20

Главный навык этой главы — отличать источник данных от курсора обхода. Если
вы удерживаете это различие, поведение циклов становится предсказуемым.

## 1. Прогнозирование вывода {#sol-ch20-01}

```python exec
numbers = [10, 20]
it = iter(numbers)
print(next(it))
print(next(it, 0))
print(list(it))
```

```output
10
20
[]
```

Второй вызов `next` вернул `20`, а не `0`: запасное значение используется
только при исчерпании, а элемент ещё был. Третий вызов через `list(it)`
получил пустой итератор — оба элемента уже забраны.

## 2. Список или итератор {#sol-ch20-02}

```python exec
items = [
    ([1, 2, 3], "список"),
    (iter([1, 2, 3]), "итератор списка"),
    ("абв", "строка"),
    (iter("абв"), "итератор строки"),
    (range(3), "range"),
]
for value, label in items:
    try:
        next(value)
        print(label, "— итератор")
    except TypeError:
        print(label, "— итерируемый объект, не итератор")
```

```output
список — итерируемый объект, не итератор
итератор списка — итератор
строка — итерируемый объект, не итератор
итератор строки — итератор
range — итерируемый объект, не итератор
```

Список, строка и `range` — источники: они выдают итератор, но сами позицию не
хранят. Объекты, полученные через `iter`, — итераторы: у них есть `next` и
состояние.

## 3. Ручной перебор {#sol-ch20-03}

```python exec
it = iter(["а", "б", "в"])
while True:
    try:
        print(next(it))
    except StopIteration:
        break
```

```output
а
б
в
```

Это ровно то, что делает `for`: получить итератор (за нас это сделал `iter`),
запрашивать элементы, а на `StopIteration` завершить цикл.

## 4. Безопасное чтение {#sol-ch20-04}

```python exec
def take_one(it):
    try:
        return next(it)
    except StopIteration:
        return "пусто"


it = iter(["единственный"])
print(take_one(it))
print(take_one(it))
```

```output
единственный
пусто
```

Того же результата можно добиться короче: `next(it, "пусто")`. Вариант с
`try`/`except` полезен, когда нужно выполнить дополнительную работу при
исчерпании.

## 5. Почему второй цикл пуст {#sol-ch20-05}

Причина: `it` — итератор, а не список. Первый цикл его исчерпал, второй
получил уже пустой курсор. Исправление первое — перебирать сам список, тогда
каждый `for` получает новый итератор:

```python exec
numbers = [1, 2]
for value in numbers:
    print(value)
for value in numbers:
    print(value)
```

```output
1
2
1
2
```

Исправление второе — создавать новый итератор перед каждым проходом:

```python exec
numbers = [1, 2]
it = iter(numbers)
for value in it:
    print(value)
it = iter(numbers)
for value in it:
    print(value)
```

```output
1
2
1
2
```

## 6. Итераторы независимы {#sol-ch20-06}

```python exec
first = iter([1, 2, 3])
second = iter([1, 2, 3])
print(next(first))
print(next(first))
print(next(second))
print(next(first))
```

```output
1
2
1
3
```

У каждого итератора своя позиция: чтение из `first` не влияет на `second`,
поэтому `second` начинает с начала, а `first` продолжает с третьего элемента.

## 7. Словарное представление {#sol-ch20-07}

```python exec
d = {"a": 1, "b": 2, "c": 3}
it = iter(d.values())
print(next(it))
print(next(it))
print(list(it))
```

```output
1
2
[3]
```

`d.values()` возвращает представление — итерируемый объект, а не итератор.
Поэтому `next(d.values())` даёт `TypeError`: сначала нужно получить итератор
через `iter`. Порядок значений совпадает с порядком ключей.

## 8. Файл как итератор {#sol-ch20-08}

```python exec
import tempfile
from pathlib import Path

with tempfile.TemporaryDirectory() as tmp:
    path = Path(tmp) / "three.txt"
    path.write_text("раз\nдва\nтри\n", encoding="utf-8")
    with open(path, encoding="utf-8") as file:
        print(next(file).strip())
        print(next(file).strip())
        for line in file:
            print(line.strip())
```

```output
раз
два
три
```

Файл сам является итератором: `next` вернул первые две строки, а цикл
продолжил с третьей. Если бы цикл начинался с начала, он повторно прочитал бы
уже прочитанные строки — но состояние обхода принадлежит файловому объекту.

## 9. Мини-проект: порционное чтение {#sol-ch20-09}

```python exec
def chunks(items, size):
    it = iter(items)
    marker = object()
    result = []
    while True:
        chunk = []
        for _ in range(size):
            value = next(it, marker)
            if value is marker:
                break
            chunk.append(value)
        if not chunk:
            break
        result.append(chunk)
    return result


print(chunks([1, 2, 3, 4, 5], 2))
print(chunks([1, 2, 3, 4], 2))
print(chunks([], 2))
print(chunks([1, 2, 3], 3))
```

```output
[[1, 2], [3, 4], [5]]
[[1, 2], [3, 4]]
[]
[[1, 2, 3]]
```

Разбор: `marker = object()` — уникальный объект, который не может случайно
оказаться элементом входа (в отличие от `None` или `0`). `next(it, marker)`
безопасно сообщает об исчерпании. Пустая порция означает конец итератора, и
цикл завершается. Срезы здесь не используются, поэтому функция работает с
любым итерируемым объектом, включая те, у которых нет индексов.

## 10. Что произойдёт с StopIteration {#sol-ch20-10}

Первая программа:

```python exec
it = iter([1])
print(next(it, None))
print(next(it, None))
```

```output
1
None
```

Запасное значение `None` вернулось вместо исключения — программа спокойно
дошла до конца.

Вторая программа:

```python exec expect-error
it = iter([1])
print(next(it))
print(next(it))
```

```output
StopIteration
```

Здесь второй `next` поднял `StopIteration`, и программа прервалась. Цикл `for`
в той же ситуации не падает: он получает `StopIteration` внутри себя,
воспринимает его как сигнал «элементы закончились» и выходит из цикла. Именно
поэтому `for` считается безопасным способом обхода, а ручные вызовы `next`
требуют внимания.

## Ответы на вопросы для самопроверки

1. Итерируемый объект умеет выдать итератор (список, строка, словарь);
   итератор выдаёт элементы и хранит позицию (результат `iter`).
2. `iter` получает итератор из итерируемого объекта; `next` запрашивает
   следующий элемент, возможно с запасным значением.
3. Список не хранит состояние обхода и не имеет `__next__`; `for` сам вызывает
   `iter` и работает с полученным итератором.
4. `StopIteration` возникает, когда у итератора больше нет элементов; в `for`
   его обрабатывает сам цикл.
5. Итератор — одноразовый курсор: позиция только движется вперёд, а признак
   исчерпания сохраняется.
6. Если элементы есть — вернёт следующий элемент, а запасное значение не
   используется; если нет — вернёт запасное значение.
7. `for` получает итератор, вызывает `next`, выполняет тело цикла с полученным
   элементом и продолжает до `StopIteration`.
