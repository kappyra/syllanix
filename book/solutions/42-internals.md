# Решения к главе 42

Решения отделены от условий. В этой главе особенно важно разделять уровни:
часть ответов описывает гарантии языка, часть — наблюдаемое поведение
CPython 3.14.4. Прогоняйте примеры на своей версии: числа и имена инструкций
могут отличаться, и это ожидаемо.

## 1. Гарантия или деталь {#sol-ch42-01}

| Утверждение | Статус | Почему |
|---|---|---|
| операнды вычисляются слева направо | гарантия языка | порядок вычислений описан в спецификации |
| удаление последней ссылки освобождает память сразу | деталь CPython | в других реализациях память освобождает сборщик |
| `int` от −5 до 256 переиспользуются | деталь CPython | кэш малых целых — оптимизация конкретной реализации |
| переменная хранит ссылку на объект | гарантия языка | модель имён и объектов описана в спецификации |
| байткод состоит из `LOAD_FAST` | деталь CPython | набор инструкций меняется между версиями |

Различие практическое. На гарантию можно опираться в переносимом коде: она не
зависит от реализации. Деталь можно использовать для диагностики и
оптимизации, но нельзя требовать. Если код ломается при смене версии Python
или реализации, чаще всего он опирался на деталь, выдав её за гарантию.

## 2. Чтение байткода {#sol-ch42-02}

```python exec
import dis

def add(a, b):
    return a + b

def show(a, b):
    print(a + b)

print("add:", [instruction.opname for instruction in dis.get_instructions(add)])
print("show:", [instruction.opname for instruction in dis.get_instructions(show)])
```

```output
add: ['RESUME', 'LOAD_FAST_BORROW_LOAD_FAST_BORROW', 'BINARY_OP', 'RETURN_VALUE']
show: ['RESUME', 'LOAD_GLOBAL', 'LOAD_FAST_BORROW_LOAD_FAST_BORROW', 'BINARY_OP', 'CALL', 'POP_TOP', 'LOAD_CONST', 'RETURN_VALUE']
```

В `add` две локальные переменные загружаются одной инструкцией, складываются и
результат возвращается. В `show` появляются новые шаги: `LOAD_GLOBAL` загружает
функцию `print`, затем вычисляется сумма, `CALL` вызывает функцию, `POP_TOP`
убирает результат вызова (он равен `None`), после чего возвращается `None`.
Список инструкций читается как рецепт для стека: каждое действие забирает
значения сверху и кладёт результат обратно.

## 3. Константные выражения {#sol-ch42-03}

```python exec
import dis

folded = compile("x = 2 * 3", "<пример>", "exec")
dynamic = compile("x = a * b", "<пример>", "exec")
print("2 * 3:", [instruction.opname for instruction in dis.get_instructions(folded)])
print("a * b:", [instruction.opname for instruction in dis.get_instructions(dynamic)])
```

```output
2 * 3: ['RESUME', 'LOAD_SMALL_INT', 'STORE_NAME', 'LOAD_CONST', 'RETURN_VALUE']
a * b: ['RESUME', 'LOAD_NAME', 'LOAD_NAME', 'BINARY_OP', 'STORE_NAME', 'LOAD_CONST', 'RETURN_VALUE']
```

В первом случае умножения нет: компилятор вычислил `2 * 3` заранее и оставил
только загрузку готового числа. Во втором случае значения известны лишь во
время исполнения, поэтому нужны две загрузки и операция. Это показывает
свободу реализации: пока результат совпадает с обещанным языком, байткод можно
менять как угодно, включая предварительные вычисления.

## 4. Размер объекта {#sol-ch42-04}

```python exec
import sys

print("int 0:", sys.getsizeof(0))
print("str пустая:", sys.getsizeof(""))
print("list пустой:", sys.getsizeof([]))
print("dict пустой:", sys.getsizeof({}))

data = [0] * 1000
print("list из 1000 элементов:", sys.getsizeof(data))
print("элементы не учтены:", sys.getsizeof(data) < 1000 * sys.getsizeof(0))
```

```output
int 0: 28
str пустая: 41
list пустой: 56
dict пустой: 64
list из 1000 элементов: 8056
элементы не учтены: True
```

`getsizeof` возвращает размер самого объекта. Для списка это массив ссылок
плюс служебные поля; тысяча нулей — это тысяча ссылок на один и тот же
закэшированный объект `int`, а не тысяча разных объектов. Поэтому сравнивать
размер контейнера с суммой размеров элементов нужно осторожно: сумма считается
по объектам, а контейнер хранит только ссылки.

## 5. Подсчёт ссылок {#sol-ch42-05}

```python exec
import sys

def demo():
    data = [1, 2, 3]
    base = sys.getrefcount(data)
    alias = data
    print("прибавка ссылок:", sys.getrefcount(data) - base)
    del alias
    print("после del:", sys.getrefcount(data) == base)

demo()
```

```output
прибавка ссылок: 1
после del: True
```

Новое имя добавляет одну ссылку, `del` убирает. Абсолютное значение зависит от
контекста, потому что сам вызов `sys.getrefcount` создаёт временную ссылку на
аргумент, а кроме того, объект может быть достижим из других мест. Поэтому
сравнивают не абсолютные числа, а их изменения — так вывод не зависит от
деталей вызова.

## 6. Цикл и сборщик {#sol-ch42-06}

```python exec
import gc, weakref

class Node:
    def __init__(self, name):
        self.name = name

cyclic = Node("цикл")
cyclic.peer = cyclic
ref = weakref.ref(cyclic)
del cyclic
print("жив после del:", ref() is not None)
collected = gc.collect()
print("жив после gc.collect:", ref() is not None)
print("сборщик нашёл объекты:", collected > 0)
```

```output
жив после del: True
жив после gc.collect: False
сборщик нашёл объекты: True
```

Подсчёт ссылок не справился, потому что объект ссылается сам на себя: счётчик
никогда не станет нулём, хотя снаружи объект недостижим. Сборщик умеет находить
такие группы и освобождать их. Значение, возвращённое `gc.collect()`, —
количество собранных объектов; оно может отличаться от единицы, потому что
сборщик учитывает и служебные структуры.

## 7. Кэш малых целых {#sol-ch42-07}

```python exec
print("256:", int("256") is int("256"))
print("257:", int("257") is int("257"))
print("сравнение по значению:", int("257") == int("257"))
```

```output
256: True
257: False
сравнение по значению: True
```

Числа от −5 до 256 в CPython закэшированы и переиспользуются, поэтому `is`
даёт `True`. За границей кэша каждый вызов `int` создаёт новый объект, и `is`
даёт `False`. Правило: `is` сравнивает идентичность объектов и уместен для
`None`, `True`, `False` и явно созданных «сторожевых» объектов; для значений
используют `==`.

## 8. Наблюдение за памятью {#sol-ch42-08}

```python exec
import tracemalloc

tracemalloc.start()
data = [bytes(1000) for _ in range(100)]
current, peak = tracemalloc.get_traced_memory()
print("текущий объём больше нуля:", current > 0)
print("пик не меньше текущего:", peak >= current)
tracemalloc.stop()
print("после stop:", tracemalloc.is_tracing())
```

```output
текущий объём больше нуля: True
пик не меньше текущего: True
после stop: False
```

Пик всегда не меньше текущего, потому что это максимум за всё время
наблюдения. После `tracemalloc.stop()` трассировка прекращается, и новые
выделения не учитываются. Точные числа зависят от интерпретатора и машины,
поэтому в проверяемом выводе остаются только инварианты.

## 9. Утечка через кэш {#sol-ch42-09}

Сборщик мусора освобождает недостижимые объекты. Запись в глобальном словаре
достижима: на неё ссылается сам словарь, а словарь — модуль, который живёт всё
время работы программы. Поэтому это не ошибка сборщика, а логическая утечка:
программа сама хранит ссылки, которые уже не нужны.

Два ограничения решают проблему. Первое — ограничение по размеру: когда записей
больше предела, удалять самые старые (политика LRU, как у `lru_cache` из
главы 40). Второе — ограничение по времени жизни: хранить время создания
записи и удалять устаревшие при добавлении новой. Оба варианта превращают
неограниченный рост в управляемый.

```python python
def remember(cache, key, value, limit=1000):
    if len(cache) >= limit:
        oldest = next(iter(cache))
        del cache[oldest]
    cache[key] = value
```

## 10. Мини-задача: отчёт о памяти {#sol-ch42-10}

```python exec
import sys

def memory_report(objects):
    counts = {}
    elements = 0
    for item in objects:
        elements += sys.getsizeof(item)
        name = type(item).__name__
        counts[name] = counts.get(name, 0) + 1
    print("типы:", sorted(counts.items()))
    print("размер контейнера:", sys.getsizeof(objects))
    print("сумма элементов:", elements)
    print("контейнер меньше суммы:", sys.getsizeof(objects) < elements)

memory_report(["один", "два", "три"])
```

```output
типы: [('str', 3)]
размер контейнера: 88
сумма элементов: 194
контейнер меньше суммы: True
```

Контейнер хранит только ссылки: три ссылки по восемь байт плюс служебные поля
дают 88 байт, тогда как сами строки занимают 194 байта. Отчёт поэтому отвечает
на два разных вопроса: сколько памяти занимает структура-контейнер и сколько
памяти занимают значения, на которые она ссылается. Для полной картины к сумме
нужно добавить размеры вложенных объектов, которые `getsizeof` не учитывает.

## Ответы на вопросы для самопроверки

1. Гарантия обязательна для всех реализаций и описана в спецификации; деталь
   реализации можно наблюдать, но нельзя требовать. Примеры гарантий: порядок
   вычисления операндов, ссылочная семантика имён. Примеры деталей: кэш малых
   целых, конкретный набор инструкций байткода.
2. Байткод — компактное и простое для исполнения представление: циклу
   интерпретатора не нужно разбирать текст на каждом шаге, а инструкции
   независимы от синтаксиса языка.
3. Цикл интерпретатора по очереди выполняет инструкции, и каждая инструкция
   имеет накладные расходы. Встроенные функции выполняют ту же работу в C,
   без расходов на интерпретацию каждой операции.
4. Любой объект начинается со счётчика ссылок и указателя на тип. Отсюда
   следует, что тип есть у каждого значения, а освобождение памяти связано с
   числом ссылок.
5. Подсчёт ссылок не освобождает циклические структуры, потому что объекты
   внутри цикла поддерживают счётчики друг друга и счётчик не доходит до нуля.
6. Сборщик находит недостижимые группы объектов и освобождает их. Время
   сборки не гарантируется: она запускается по порогам или по явному вызову.
7. `getsizeof` контейнера возвращает размер самого контейнера и его массива
   ссылок, а не объектов, на которые эти ссылки указывают.
8. `is` проверяет идентичность объектов. Для чисел результат зависит от кэша и
   оптимизаций компилятора, поэтому он не переносим; для значений есть `==`.
