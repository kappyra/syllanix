# Решения к главе 41

Безопасность — область, где «работает» и «правильно» не одно и то же. В
решениях обращайте внимание не только на результат, но и на то, где стоит
проверка и почему именно там. Запускайте примеры: все выводы детерминированы.

## 1. Границы доверия {#sol-ch41-01}

Пять источников и их оценка:

| Источник | Доверие | Где проверка |
|---|---|---|
| текст заметки из формы | недоверенный | на входе API: длина, тип, допустимые символы |
| имя пользователя из сессии | условно доверенный | подпись сессии проверяется при аутентификации |
| ответ внешнего API погоды | недоверенный | схема ответа до использования |
| значение из переменной окружения | недоверенный | при старте: наличие, формат, диапазон |
| строка из вашей базы | недоверенный | при записи (валидация) и при чтении (схема) |

Строка из базы недоверенна, потому что база — общий ресурс: туда пишут другие
сервисы, миграции и иногда люди. Доверие к данным определяется не местом
хранения, а тем, кто мог их изменить. Проверка на записи защищает от
некорректных данных, проверка на чтении — от того, что было записано в обход
проверок.

## 2. Валидация по белому списку {#sol-ch41-02}

```python exec
ALLOWED_STATUSES = {"new", "in_progress", "done"}

def parse_status(raw):
    if not isinstance(raw, str):
        raise ValueError("статус должен быть строкой")
    status = raw.strip()
    if status not in ALLOWED_STATUSES:
        allowed = ", ".join(sorted(ALLOWED_STATUSES))
        raise ValueError(f"недопустимый статус {status!r}; ожидается один из: {allowed}")
    return status

for value in ("new", " done ", "archived", 42):
    try:
        print(repr(value), "->", parse_status(value))
    except ValueError as error:
        print(repr(value), "->", error)
```

```output
'new' -> new
' done ' -> done
'archived' -> недопустимый статус 'archived'; ожидается один из: done, in_progress, new
42 -> статус должен быть строкой
```

Белый список хорош тем, что множество допустимых значений закрыто: любое
неизвестное значение отклоняется, даже если оно выглядит безопасным.
Сообщение об ошибке перечисляет допустимые варианты — это удобно и не
раскрывает ничего лишнего.

## 3. Поиск инъекции {#sol-ch41-03}

Параметр `order_id` подставляется в текст запроса, поэтому кавычка или
оператор в нём меняют смысл запроса. Значение `1 OR 1=1` превращает условие в
истинное для всех строк, а `1; DROP TABLE orders` может выполнить вторую
команду, если драйвер разрешает несколько инструкций. Тип аргумента должен
стать числом, которое передаётся отдельно.

```python exec
import sqlite3

connection = sqlite3.connect(":memory:")
connection.execute("CREATE TABLE orders (id INTEGER, title TEXT)")
connection.executemany("INSERT INTO orders VALUES (?, ?)", [(1, "первый"), (2, "второй")])

def find_order_unsafe(order_id):
    query = "SELECT * FROM orders WHERE id = " + order_id
    return connection.execute(query).fetchall()

print("обычно:", find_order_unsafe("1"))
print("инъекция:", find_order_unsafe("1 OR 1=1"))

def find_order_safe(order_id):
    query = "SELECT * FROM orders WHERE id = ?"
    return connection.execute(query, (order_id,)).fetchall()

print("безопасно:", find_order_safe("1 OR 1=1"))
```

```output
обычно: [(1, 'первый')]
инъекция: [(1, 'первый'), (2, 'второй')]
безопасно: []
```

Безопасная версия принимает значение как параметр: драйвер отправляет запрос
и данные раздельно, поэтому `1 OR 1=1` сравнивается с `id` как строка и не
находит совпадений. В реальном коде аргумент дополнительно приводят к `int`
и проверяют, но защиту даёт именно параметризация.

## 4. Команда без оболочки {#sol-ch41-04}

`shell=True` означает «передай строку оболочке». Оболочка разбирает строку по
спецсимволам: `;`, `&&`, `|`, `$()`. Если имя хоста пришло от пользователя, он
может дописать свою команду, и она выполнится с правами процесса. Даже
экранирование не решает проблему надёжно: правил разбора много, а ошибка
стоит дорого.

Правильный вызов передаёт команду и аргументы списком, без оболочки:

```python python
import subprocess

host = "example.com; echo взломано"
subprocess.run(["ping", "-c", "1", "--", host], check=True)
```

Здесь `host` — один аргумент, а не часть командной строки: `ping` получит
строку целиком и попытается разрешить такое имя. Символ `;` не имеет
специального смысла, потому что оболочки в цепочке нет. `shell=True` нужен
только тогда, когда действительно требуется синтаксис оболочки, и в этом
случае аргументы собирают максимально жёстко.

## 5. Секреты в логах {#sol-ch41-05}

Три уровня исправления.

**Код.** Не логировать объект конфигурации целиком. Логировать только
безопасные поля и явно маскировать секреты:

```python python
def safe_dsn(config):
    return f"postgresql://{config['user']}:***@{config['host']}/{config['database']}"
```

**Конфигурация.** Хранить секрет отдельно от остальных настроек, чтобы он не
попадал в дампы конфигурации: переменная окружения или хранилище секретов.
Логирование конфигурации при старте должно явно исключать секретные ключи.

**Проверка.** Добавить тест, который перехватывает записи логгера и проверяет,
что значение секрета не встречается в отформатированных сообщениях. Такой тест
ловит регрессию, когда кто-то снова начнёт логировать весь словарь. Дополнительно
включите маскирование на уровне форматтера — тогда даже случайная запись
секрета не попадёт в вывод.

## 6. Хеширование пароля {#sol-ch41-06}

```python exec
import hashlib, hmac

def hash_password(raw, salt):
    return hashlib.scrypt(raw.encode(), salt=salt, n=2**14, r=8, p=1, dklen=32)

def verify_password(raw, salt, stored):
    return hmac.compare_digest(stored, hash_password(raw, salt))

salt = b"unique-salt-for-record"
stored = hash_password("долгий пароль 2026", salt)
print(verify_password("долгий пароль 2026", salt, stored))
print(verify_password("короткий", salt, stored))
```

```output
True
False
```

Соль делает хеши уникальными: два пользователя с одинаковым паролем получат
разные отпечатки, поэтому заранее вычисленные таблицы бесполезны. `scrypt`
намеренно требует памяти и времени, что делает перебор дорогим. `sha256`
здесь не подходит: он быстрый, и миллионы вариантов проверяются за секунды.
`hmac.compare_digest` сравнивает отпечатки за постоянное время, чтобы по
задержке нельзя было угадывать пароль посимвольно.

## 7. Опасная десериализация {#sol-ch41-07}

`pickle` при загрузке восстанавливает объекты и может вызвать произвольную
функцию, указанную в данных. Атакующий присылает не «данные о пользователе»,
а программу, которая выполнится на сервере с его правами: прочитает файлы,
отправит данные наружу, изменит базу. Замена — разбор JSON с проверкой полей.

```python exec
import json

def parse_user(raw):
    data = json.loads(raw)
    if not isinstance(data, dict):
        raise ValueError("ожидается объект")
    name = data.get("name")
    age = data.get("age")
    if not isinstance(name, str) or not 2 <= len(name) <= 40:
        raise ValueError("name: ожидается строка от 2 до 40 символов")
    if not isinstance(age, int) or isinstance(age, bool) or not 0 <= age <= 130:
        raise ValueError("age: ожидается целое от 0 до 130")
    return {"name": name, "age": age}

print(parse_user('{"name": "anna", "age": 30}'))
try:
    parse_user('{"name": "a", "age": 200}')
except ValueError as error:
    print("отклонено:", error)
```

```output
{'name': 'anna', 'age': 30}
отклонено: name: ожидается строка от 2 до 40 символов
```

`json.loads` возвращает только данные: строки, числа, списки, словари, `None`.
Никаких вызовов функций формат не предусматривает. После разбора поля
проверяются по типам и диапазонам — это и есть валидация на границе.

## 8. Уязвимая зависимость {#sol-ch41-08}

Порядок действий:

1. **Зафиксировать исправление.** Обновить версию в файле зависимостей до
   `1.2.3` и пересобрать `lockfile`, чтобы зафиксировались точные версии всех
   транзитивных пакетов.
2. **Проверить совместимость.** Прогнать тесты и, если есть, статическую
   проверку типов. Обновление внутри патч-версии обычно совместимо, но
   проверить нужно именно свой проект.
3. **Проверить, что уязвимость закрыта.** Повторить аудит зависимостей: он
   должен перестать показывать проблему.
4. **Выпустить.** Зафиксировать в changelog причину обновления, чтобы при
   следующем аудите было понятно, зачем менялась версия.

Если обновление невозможно (например, новая версия требует другого Python),
варианты такие: найти промежуточную версию с исправлением, заменить библиотеку,
изолировать уязвимый вызов, ограничив входные данные, и зафиксировать риск с
датой пересмотра. Игнорировать уязвимость нельзя: она остаётся, даже если о
ней не вспоминать.

## 9. Наименьшие привилегии {#sol-ch41-09}

```python exec
class UserReportSource:
    def __init__(self, name, created_at, email, token):
        self.name = name
        self.created_at = created_at
        self.email = email
        self.token = token

    def report_view(self):
        return {"name": self.name, "created_at": self.created_at}

def build_report(view):
    return f"{view['name']} зарегистрирован {view['created_at']}"

source = UserReportSource("anna", "2026-01-01", "anna@example.com", "secret-token")
print(build_report(source.report_view()))
```

```output
anna зарегистрирован 2026-01-01
```

`build_report` получает словарь из двух полей: почты и токена в нём физически
нет. Если функция начнёт логировать весь аргумент, утечки не произойдёт.
Ограничение интерфейса надёжнее дисциплины: правило «не логируй лишнее» можно
забыть, а отсутствующее поле не появится в логе.

## 10. Мини-задача: безопасная регистрация {#sol-ch41-10}

```python exec
import hashlib, re, secrets

def register(payload, salt=None):
    problems = []
    name = payload.get("name")
    email = payload.get("email")
    password = payload.get("password")
    if not isinstance(name, str) or not 2 <= len(name) <= 40:
        problems.append("name: от 2 до 40 символов")
    if not isinstance(email, str) or not re.fullmatch(r"[^@\s]+@[^@\s]+\.[^@\s]+", email):
        problems.append("email: неверный формат")
    if not isinstance(password, str) or len(password) < 12:
        problems.append("password: короче 12 символов")
    if problems:
        raise ValueError("; ".join(problems))
    salt = salt or secrets.token_bytes(16)
    digest = hashlib.scrypt(password.encode(), salt=salt, n=2**14, r=8, p=1, dklen=32)
    return {"name": name, "email": email, "salt": salt.hex(), "password_hash": digest.hex()}

record = register({"name": "anna", "email": "anna@example.com", "password": "длинный пароль"})
print("поле пароля:", "password" in record)
print("есть хеш:", len(record["password_hash"]) == 64)
try:
    register({"name": "a", "email": "плохо", "password": "коротко"})
except ValueError as error:
    print("ошибки:", error)
```

```output
поле пароля: False
есть хеш: True
ошибки: name: от 2 до 40 символов; email: неверный формат; password: короче 12 символов
```

Функция собирает все проблемы сразу, а не падает на первой: пользователю проще
исправить три поля за раз. В результат попадают только безопасные поля и
производные значения — соль и хеш. Сам пароль не сохраняется нигде и не
возвращается. Проверка формата почты здесь упрощённая и служит примером;
в рабочем коде её дополняют подтверждением адреса.

## Ответы на вопросы для самопроверки

1. Граница доверия разделяет код и данные извне. Данные из базы могут быть
   изменены другим сервисом или человеком, поэтому доверие определяется
   источником изменения, а не местом хранения.
2. Валидация решает, допустимо ли значение; экранирование — как безопасно
   встроить его в конкретный синтаксис. Валидация без экранирования пропустит
   допустимое значение в опасный контекст, экранирование без валидации
   пропустит бессмысленные данные.
3. Параметризация передаёт данные отдельным каналом, и интерпретатор не
   разбирает их как код. Экранирование кавычек помогает только для конкретного
   синтаксиса и легко обходится в другом месте.
4. Соль исключает одинаковые отпечатки для одинаковых паролей, а медленный
   алгоритм делает перебор дорогим по времени и памяти.
5. `pickle` может вызвать произвольную функцию при загрузке. Вместо него
   используют JSON, CSV и другие форматы данных с последующей валидацией.
6. Уязвимость зависимости — известная проблема в сторонней библиотеке. Замок
   версий фиксирует точный набор пакетов, поэтому обновление исправленной
   версии и воспроизводимость сборки становятся управляемыми.
7. Ограничение прав сокращает ущерб: скомпрометированная часть системы может
   сделать только то, на что у неё есть права.
8. Проверку в браузере можно обойти, отправив запрос напрямую; решение о
   доступе принимается на сервере.
