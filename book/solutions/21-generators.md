# Решения к главе 21

Генераторы требуют новой привычки чтения: тело функции исполняется не в
момент вызова, а по шагам, в момент запроса. Если вы удерживаете это в
голове, порядок вывода перестаёт быть загадкой.

## 1. Прогнозирование вывода {#sol-ch21-01}

```python exec
def speak():
    print("начало")
    yield 1
    print("середина")
    yield 2
    print("конец")


gen = speak()
print(next(gen))
print(next(gen))
print(next(gen, "пусто"))
```

```output
начало
1
середина
2
конец
пусто
```

Каждый `next` исполняет тело до очередного `yield`: перед первым значением
печатается `начало`, перед вторым — `середина`, после второго значения
исполнение доходит до `конец` и поднимает `StopIteration`, поэтому третий
`next` вернул запасное значение.

## 2. Первый генератор {#sol-ch21-02}

```python exec
def countdown(n):
    while n > 0:
        yield n
        n = n - 1


print(list(countdown(3)))
for value in countdown(3):
    print(value)
```

```output
[3, 2, 1]
3
2
1
```

`list(countdown(3))` и цикл `for` каждый раз создают новый генератор, поэтому
оба прохода начинаются с `3`.

## 3. Ленивость на практике {#sol-ch21-03}

```python exec
def naturals(limit):
    n = 1
    while n <= limit:
        print("вычисляю", n)
        yield n
        n = n + 1


count = 0
for value in naturals(100):
    print("получили", value)
    count = count + 1
    if count == 3:
        break
```

```output
вычисляю 1
получили 1
вычисляю 2
получили 2
вычисляю 3
получили 3
```

`вычисляю` напечаталось ровно три раза: генератор не знает, что задумано сто
элементов, и не вычисляет их заранее. После `break` генератор просто
перестаёт использоваться.

## 4. Генераторное выражение {#sol-ch21-04}

```python exec
gen = (x * 2 for x in [3, 1, 4, 1, 5])
print(next(gen))
print(next(gen))
print(list(gen))
```

```output
6
2
[8, 2, 10]
```

Первые два значения забраны по одному, `list` получил остаток. Генераторное
выражение не строит список из пяти удвоенных чисел: значения вычисляются по
запросу.

## 5. Сумма без списка {#sol-ch21-05}

```python exec
print(sum(x * x for x in range(1, 101)))
```

```output
338350
```

`sum` принимает итерируемый объект и забирает элементы по одному. Промежуточный
список из ста квадратов не создаётся: каждое значение вычисляется и сразу
прибавляется к сумме.

## 6. Исчерпание {#sol-ch21-06}

Причина: генераторное выражение создаёт один генератор, а первый `list`
доводит его до исчерпания. Второй `list` получает пустой генератор.

```python exec
gen = (n for n in [1, 2])
print(list(gen))
print(list(gen))
```

```output
[1, 2]
[]
```

Исправление первое — перебирать исходный список, тогда каждый `list` создаёт
новый генератор:

```python exec
numbers = [1, 2]
print(list(n for n in numbers))
print(list(n for n in numbers))
```

```output
[1, 2]
[1, 2]
```

Исправление второе — создать генератор заново перед вторым проходом:

```python exec
gen = (n for n in [1, 2])
print(list(gen))
gen = (n for n in [1, 2])
print(list(gen))
```

```output
[1, 2]
[1, 2]
```

## 7. Ранний выход {#sol-ch21-07}

```python exec
def first_even(numbers):
    for n in numbers:
        if n % 2 == 0:
            yield n
            return


print(list(first_even([3, 5, 8, 10])))
```

```output
[8]
```

После `yield` выполняется `return`, генератор завершается, и `list` получает
`StopIteration`. Поэтому в результате только одно число: `10` даже не было
рассмотрено.

## 8. Конвейер {#sol-ch21-08}

```python exec
def numbers(limit):
    n = 1
    while n <= limit:
        yield n
        n = n + 1


def odds(items):
    for item in items:
        if item % 2 == 1:
            yield item


def squared(items):
    for item in items:
        yield item * item


print(list(squared(odds(numbers(10)))))
```

```output
[1, 9, 25, 49, 81]
```

Через первый этап проходят все 10 чисел, через второй — 5 нечётных, третий
выдаёт 5 квадратов. Промежуточные списки не создаются: каждый элемент
продвигается по цепочке отдельно.

## 9. Мини-проект: строки с ключевым словом {#sol-ch21-09}

```python exec
import tempfile
from pathlib import Path


def find_lines(path, keyword):
    with open(path, encoding="utf-8") as file:
        for line in file:
            if keyword in line:
                yield line.strip()


with tempfile.TemporaryDirectory() as tmp:
    path = Path(tmp) / "journal.txt"
    path.write_text("старт\nошибка 1\nшаг\nошибка 2\nфиниш\n", encoding="utf-8")
    for line in find_lines(path, "ошибка"):
        print(line)
```

```output
ошибка 1
ошибка 2
```

Файл читается построчно: генератор не вызывает `readlines` и не собирает все
строки в память. Если обход прервать после первой находки, оставшиеся строки
не будут прочитаны вовсе. Инструкция `with` внутри генератора закрывает файл,
когда генератор завершается.

## 10. Генератор или список {#sol-ch21-10}

- первые 10 членов последовательности — генератор: нужна только часть
  значений, и последовательность может быть бесконечной;
- отсортировать все оценки по убыванию — список: сортировке нужен полный
  набор элементов, и результат всё равно хранится целиком; `sorted` принимает
  и генератор, но это не делает сортировку ленивой;
- сумма чисел из файла — генератор: значения нужны один раз и по порядку;
- результат, который будут перебирать трижды — список: генератор после
  первого прохода исчерпается.

Пример генератора для первой задачи:

```python exec
def first_ten():
    n = 1
    while n <= 10:
        yield n * n
        n = n + 1


print(list(first_ten()))
```

```output
[1, 4, 9, 16, 25, 36, 49, 64, 81, 100]
```

Пример списка для второй задачи:

```python exec
grades = [4, 5, 3]
grades.sort(reverse=True)
print(grades)
```

```output
[5, 4, 3]
```

Список здесь необходим: сортировать можно только коллекцию, в которой есть все
элементы, а перебирать результат предполагается несколько раз.

## Ответы на вопросы для самопроверки

1. Вызов создаёт генератор; тело начинает исполняться при первом запросе
   элемента через `next` или `for`.
2. `yield` выдаёт значение и приостанавливает функцию, сохраняя состояние;
   `return` завершает генератор, значения в цикл не передаёт.
3. Ленивые вычисления выполняют работу только при необходимости; экономия —
   память под элементы и время на ненужные вычисления.
4. Генератор — одноразовый итератор: после исчерпания он пуст.
5. Генераторное выражение создаёт генератор, а не кортеж или список;
   заключённое в скобки выражение вычисляется сразу.
6. `list` попытается забрать все элементы и не завершится; выборку нужно
   ограничивать (`break`, `next` несколько раз).
7. Генератор — частный случай итератора: он реализует протокол итерации и
   сигнализирует о конце через `StopIteration`.
