# Решения к главе 2

Решения отделены от условий, чтобы вы могли сначала попробовать сами.
Запускайте код и сравнивайте с объяснением: важно не «увидеть ответ», а
понять, почему он такой.

## 1. Арифметика вручную и на компьютере {#sol-ch02-01}

```python exec
print(17 // 5)
print(17 % 5)
print(2 ** 8)
print(7 / 2)
```

```output
3
2
256
3.5
```

Связь: `17 = 5 * 3 + 2`, то есть делимое равно произведению делителя на
целую часть плюс остаток. Это универсальное тождество для целых чисел:
`a = b * (a // b) + (a % b)` при `b != 0`.

## 2. Прогнозирование вывода {#sol-ch02-02}

```python exec
print(3, 4, sep="+")
print(3, 4)
```

```output
3+4
3 4
```

`sep="+"` заменяет разделитель по умолчанию (пробел) на плюс.

## 3. Исправление синтаксической ошибки {#sol-ch02-03}

В строке `print("Python` не закрыта кавычка, поэтому интерпретатор не может
определить, где заканчивается строковый литерал. Исправление — закрыть и
кавычку, и скобку:

```python exec
print("Python")
```

```output
Python
```

## 4. Соединение строк {#sol-ch02-04}

```python exec
print("Python" + " — " + "это язык")
```

```output
Python — это язык
```

Пробелы вокруг тире добавлены как отдельные строки: без них получилось бы
`Python— это язык`, потому что `+` не вставляет пробелов автоматически.

## 5. Целое или дробное {#sol-ch02-05}

Оператор `/` в Python 3 всегда возвращает число с плавающей точкой, поэтому
`10 / 2` даёт `5.0` (тип `float`). Целое значение получается целочисленным
делением `//`:

```python exec
print(10 / 2)
print(10 // 2)
```

```output
5.0
5
```

## 7. Ошибка времени выполнения {#sol-ch02-07}

Тип ошибки — `TypeError`: оператор `+` не определён для пары «строка, число».

```python exec expect-error
print("итог: " + 42)
```

```output
TypeError: can only concatenate str (not "int") to str
```

Два исправления:

```python exec
print("итог: " + str(42))
print("итог:", 42)
```

```output
итог: 42
итог: 42
```

Первый вариант превращает число в строку и соединяет строки. Второй передаёт
два значения в `print`, который сам вставит пробел.

## 8. Деление на ноль {#sol-ch02-08}

```python exec expect-error
print(5 // 0)
```

```output
ZeroDivisionError: division by zero
```

Исключение то же — `ZeroDivisionError`. В Python 3.14 сообщение для всех
операций деления одинаковое (`division by zero`), а в версиях до 3.14 для `//`
и `%` было `integer division or modulo by zero`. Делить на ноль нельзя ни в
каком виде; на текст сообщения опираться не стоит, на тип исключения — можно.

## 10. Мини-задача: стоимость заказа {#sol-ch02-10}

Товары: `3 * 250 = 750` рублей. Скидка 10 % — это `750 * 10 // 100 = 75`
рублей. Итог: `750 - 75 = 675` рублей.

```python exec
print(3 * 250 - 3 * 250 * 10 // 100)
```

```output
675
```

Целое число получается благодаря `//`: скидка вычисляется в целых рублях.
Если использовать `/`, результат стал бы `675.0` — число с плавающей точкой.
Обратите внимание на порядок операций: умножение и деление выполняются раньше
сложения и вычитания, поэтому `3 * 250 * 10 // 100` вычисляется как
`(3 * 250 * 10) // 100`.

## Ответы на вопросы для самопроверки

1. Выражение вычисляется в значение (`2 + 3`, `"текст"`); инструкция
   выполняется, но не обязана давать значение (`print(...)`, `import os`).
2. `/` — обычное деление, всегда результат типа float; `//` — целочисленное
   деление, округляет вниз к меньшему целому.
3. `sep` — разделитель между значениями; `end` — то, что добавляется после
   последнего значения (по умолчанию перевод строки).
4. `+` для строк определён только как соединение двух строк; число нужно
   сначала превратить в строку функцией `str`.
5. `SyntaxError` возникает при разборе до запуска и не даёт программе
   стартовать; `ZeroDivisionError` — во время исполнения, после того как часть
   программы уже выполнилась.
6. Ошибка времени выполнения появляется на этапе исполнения байткода, когда
   очередная операция не может быть выполнена с данными, которые ей передали.
