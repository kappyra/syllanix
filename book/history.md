# История и философия Python

Эта страница — о том, откуда взялся язык, каким принципам он следует и почему
код на Python выглядит именно так, а не иначе. Понимание истории объясняет
многие решения, которые иначе кажутся произвольными.

## 1. До Python: языки, из которых он вырос

В конце 1980-х Гвидо ван Россум работал в исследовательском институте CWI
(Нидерланды) над языком **ABC** — учебным языком для начинающих. ABC был
красивым экспериментом: отступы вместо фигурных скобок, встроенные
коллекции, интерактивная среда. Но он плохо расширялся и не подходил для
системных задач.

Python задумывался как язык, который соединит **читаемость ABC** с
**практичностью C** и возможностью расширения. Первая публичная версия
появилась в **1991 году**; название — отнюдь не от змеи: оно отсылает к
комедийному сериалу «Летающий цирк Монти Пайтона».

С самого начала язык развивался как открытый проект: исходный код доступен,
решения обсуждаются сообществом, а не только автором.

## 2. Ключевые вехи

| Год | Событие | Почему важно |

| 1994 | Python 1.0 | лямбды, `map`/`filter`, модульная система |

| 2020 | Python 3.9 | `dict` с объединением, новый синтаксис типов |

Развитие продолжается предсказуемо: новая версия выходит раз в год,
несовместимые изменения вводятся через длительный период предупреждений
(механизм **deprecation**).

## 3. Python 2 → Python 3: урок совместимости

Переход на Python 3 — самый поучительный эпизод истории языка. Ради чистоты
пришлось сломать обратную совместимость: `print` стал функцией, строки стали
Unicode по умолчанию, целочисленное деление изменило поведение.

Последствия:

- переход занял больше десяти лет — дольше, чем планировалось;
- появились инструменты автоматической миграции (`2to3`, `six`);
- сообщество выучило урок: **ломать совместимость дорого**, лучше готовить
  изменения заранее.

Отсюда современный процесс **PEP** (Python Enhancement Proposal): любое
существенное изменение оформляется документом, обсуждается и фиксируется.
Поэтому в книге мы различаем гарантии языка, поведение конкретной версии и
рекомендации — это прямое следствие этой инженерной культуры.

## 4. Философия: Zen of Python

В 1999 году Тим Питерс сформулировал принципы дизайна языка — **PEP 20**,
известный как «Zen of Python». Его можно прочитать в любой установке:

```console
$ python3 -m this
```

Основные идеи, которые видно в каждой строке кода на Python:

- **Читаемость важнее краткости.** Код читают чаще, чем пишут.
- **Явное лучше неявного.** Не должно быть «магии», о которой нужно
  догадываться.
- **Простое лучше сложного; сложное лучше запутанного.** Сложность
  допускается, но она должна быть оправдана.
- **Плоское лучше вложенного.** Глубокая вложенность ухудшает понимание.
- **Разреженное лучше плотного.** Не нужно упаковывать всё в одну строку.
- **Особые случаи не настолько особые, чтобы нарушать правила.**

Философия — не догма, а критерий для инженерных решений. В книге мы будем
ссылаться на неё, объясняя, почему одна запись считается «питонической», а
другая — нет (подробно — в главе 50).

## 5. Версии и экосистема сегодня

- **Актуальная стабильная версия** — Python 3.14 (на ней проверяется книга);
  минимум — 3.11.
- **Реализации**: CPython (эталон), PyPy (JIT-ускорение), MicroPython
  (микроконтроллеры), free-threaded сборка CPython (экспериментальная работа
  без GIL).
- **Пакеты**: PyPI — крупнейший индекс библиотек; `pip`, `uv`, `poetry` —
  менеджеры зависимостей (глава 33).
- **Инструменты**: `pytest`, `ruff`, `mypy`, `black` — стандарт де-факто
  качества кода (главы 32, 33, 49).
- **Сообщество**: PyCon, локальные сообщества, PEP-процесс, тысячи открытых
  библиотек.

Python применяется в веб-разработке, анализе данных, машинном обучении,
автоматизации, научных расчётах, инфраструктуре и тестировании. Это язык
«общего назначения с сильной экосистемой библиотек» — и книга учит не только
синтаксису, но и работе с этой экосистемой.

## 6. Почему история полезна на практике

1. **Объясняет несовместимости.** Зная про Python 2/3, вы понимаете, почему
   часть кода в интернете устарела.
2. **Объясняет стиль.** Отступы, отказ от скобок, «явное лучше неявного» —
   следствие исходного замысла, а не случайность.
3. **Защищает от мифов.** «Python медленный» — верно для одних задач и
   неверно для других; правильный разговор — про профилирование (главы 40,
   52), а не про ярлыки.
4. **Помогает читать чужой код.** Вы понимаете, какие решения считались
   хорошими в момент их принятия.
